## 1. 准备环境

1. 保存当前工作，在 `chrome://extensions` 重新加载本仓库最新 `luban/dist`，关闭旧侧栏和设置页再打开。侧栏品牌应有 V2.1 标识。
2. 记录 Chrome 版本、扩展 ID、模型及日期；构建以 `evidence/v2.1-source-sha256.json` 对照，不仅靠 manifest 的版本号。
3. 从仓库根目录，在两个终端分别运行并保持窗口打开：

```sh
python3 -m http.server 18888 --bind 127.0.0.1 --directory luban/spike-v2
```

```sh
python3 luban/spike-v2/v21-compatible-server.py
```

4. 打开 `http://localhost:18888/fixture.html`。初始 WAITING 正常。
5. 先记住原模型配置；设置中启用自定义端点，Base URL `http://localhost:18921/v1`，Key `local-test-key`，模型先用 `v21-good`，保存并完成授权。localhost 之前已授权时不会再弹窗。
6. 点击测试连接，应成功。失败先检查服务是否仍运行；这不是在线模型服务。

- [ ] 环境和受控服务准备完成

## 2. 简单任务：检查、试运行、效果保存（O02/O10/O11）

1. 新建工具，需求“在 #result 显示 V21 READY，不影响其他内容”。
2. 查看发送内容；简单整页任务不强制确认模块策略。确认首次请求及“最多一次追加修复”说明。
3. 确认生成，应出现“检查通过，可试运行”，页面此时仍是 WAITING。
4. 填工具名称 `V21 简单测试-唯一后缀`，点击确认试运行。
5. 页面显示 V21 READY；结果应说“执行已完成，请检查页面效果”，不能说已自动验证视觉效果。
6. 点击“继续观察”，确认没有自动保存。再点击“效果符合，保存”，保存成功，自动运行默认关闭。

- [ ] 简单路径没有多余策略确认

## 3. 基础错误与受控修复（O01/O04/O06）

### 3.1 稳定触发一次修复

1. 设置中将本地模型改成 `v21-undefined` 并保存。
2. 新建独立工具，输入相同需求，保持“允许基础检查失败时自动修复一次”开启。
3. 预览确认后生成；应识别多余变量 n，追加一次修复，最后显示可试运行。
4. 结果记录应为请求 2 次、首次未通过、修复后通过。页面未提前执行。
5. 试运行后显示 V21 READY，再由你确认保存。

### 3.2 关闭修复

1. 同模型另建工具，关闭修复选项，预览应说明最多 1 次请求。
2. 生成应提示未定义 n 和位置；请求数 1，原稿不被失败候选覆盖。
3. 展开失败候选，确认有 n。选择显式复制为未验证草稿后，检查仍不能放行 n。

### 3.3 手改代码

1. 在已成功工具中编辑代码，加一行 `n;`。
2. 原试运行/保存资格应失效。点击“检查当前草稿”，显示 n 的正确正文行号。
3. 手动输入/检查期间没有模型请求。
4. 点击“查看修复发送内容”，检查带入的是手改代码。确认后才调用模型；手动修复入口本次最多 1 次请求。
5. 或自行删除 n，重新检查、试运行、确认效果再保存。
6. 另用注释/字符串提及 GM API，不应误报缺权限；实际调用 GM_getValue 时仍须在折叠的“草稿 GM 权限”中声明。

- [ ] 一次自动修复、关闭修复、手改检查通过
- [ ] 原稿与保存版保护通过

## 4. 不完整、范围变化和共享预算（O03/O04/O05/O14）

使用不同的新工具，逐个切换本地模型并保存：

| 模型 | 操作与预期 |
|---|---|
| `v21-truncated` | 生成提示输出上限/不完整，不能试运行半成品，只有 1 次请求，不机械补括号 |
| `v21-scopechange` | 首次 n、第二次改变原文字；应提示修复范围无法确认，原草稿不被替换，候选可展开并由用户主动复制 |
| `v21-format` | 首次格式错误、第二次仍含 n；应停止，总请求数 2，不出现第三次修复 |

在 SW DevTools Network 中检查实际 `chat/completions` 请求数；不要导出含认证头的 HAR。质量统计同时保留首次失败与修复结论，不能把追加成功记为首次成功。

真实限流/网络超时可在独立测试环境验证：应保留原稿，不连续自动重发。无法稳定触发时引用自动检查，不冒充真实网络验收。

- [ ] 截断、范围变化、格式与代码共享预算通过
- [ ] 请求数与界面一致；错误不泄露 Key

## 5. 真实目标范围与策略确认（O07/O09/O10）

先恢复你原本可用的真实模型配置。受控服务固定只改 #result，不能用于验证豆瓣真实效果。

1. 打开实际豆瓣页面，记录完整 URL 和待隐藏广告，点击鲁班图标授权。
2. 新建工具，点选广告主体。查看“单个元素”及上级候选；候选并非自动判定广告，需你核对。
3. 从作用范围选择包含广告主体、广告标签及占位的最小容器，不选整个侧栏。
4. 点击预览范围，应只有临时高亮，网页尚未被隐藏；Esc 清除高亮，需求仍在。
5. 填保留约束“保留正文与相邻推荐”，完整模块应出现策略卡；确认范围后继续。
6. 若任务需要点击后、变化时或延时执行，在“触发方式与预期效果”中明确选择；不应统一误写成立即执行。
7. 查看实际发送消息，包含确认目标、有限祖先/相邻摘要和保留约束，不含整页 HTML 或 Key。
8. 生成并试运行：主体、标签、占位应一起消失，正文及相邻推荐不变。div 仍留在 DOM 但不占位可通过。
9. 若没有可靠候选，重新点选；系统不应猜测站点选择器或把整个侧栏自动当目标。
10. 重新加载页面后，旧点选绑定应失效，需重新点选。目标已消失或多个匹配时应明确提示。

- [ ] 范围预览只读、自身高亮不入选、完整模块效果通过
- [ ] 简单/复杂路径、触发方式与页面变化保护通过

## 6. 多轮反馈与约束（O08/O13）

1. 同一工具首次仅隐藏广告主体时，点击继续反馈，选“标签还在”或“仍有空白”。快捷项只填输入，不能立即请求或执行。
2. 补充“隐藏最小完整广告容器，保留相邻推荐”，必要时重新点选/选择模块并重新确认策略。
3. 查看发送内容，基线为当前草稿/手改代码，包含有效保留约束和反馈。
4. 再生成、试运行，确认标签和空白消失；保存应更新原工具，不增加重复工具。
5. 对话保留本轮反馈与修正说明。若模型返回目标/约束冲突问题，应展示待澄清卡，原草稿不被空代码覆盖。
6. A/B 工具及新建草稿交替使用，代码、约束、反馈、错误和失败候选不串联。
7. 关闭面板重开，已持久数据可恢复；目标句柄失效时重新点选，不自动重新发送请求。

- [ ] 多轮反馈、手改基线、约束和工作区隔离通过

## 7. 取消、并发、核心回归（O05/O11/O12/O16）

1. 真实模型较慢时取消生成/修复，原稿及输入保留；晚到结果不替换。新请求可重新开始。
2. 发送预览后切换页面或更改模型配置，再确认应失效；在途页面变化结果不可提交。
3. 侧栏和设置页同时打开同一工具，一处更新后另一处旧提交应报冲突，不覆盖新版本。
4. 试运行后修改代码/grants/范围/约束，旧效果保存资格失效，需重试运行。
5. 脚本自身修改目标外观或文本后，仍可确认保存；之后目标又发生非本轮变化则需重新验证。
6. 已保存 A → 修改保存 B → 开自动运行 → 不点图标新开匹配页验证 B → 恢复 A → 刷新验证 A → 导出 A → 停用，新页不运行。
7. GM 读写/null/delete 保持正常，代码恢复不回退 GM；原有 P7 分析与自定义端点仍可用。
8. 延时、监控、提取任务初始化无异常时，只提示继续观察/检查对应结果，不虚报长期完成。

- [ ] 取消、并发、旧凭证与页面身份保护通过
- [ ] 创建/自动/恢复/导出及 GM/P7 回归通过
