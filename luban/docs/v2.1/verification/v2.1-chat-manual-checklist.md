# V2.1 Chat R2 人工验收清单

日期：2026-10-15。依据：[需求 C01–C14](../v2.1-optimization-requirements.md)、[技术方案](../v2.1-technical-design.md)。本清单验证正式扩展，不是 Demo。未勾选表示尚未收到真实 Chrome 验收结果。

## 0. 环境与证据

1. 在项目 `luban` 下执行 `npm run build`（本轮已构建）。在 `chrome://extensions` 找到鲁班，点击重新加载，加载目录应为 `luban/dist`。
2. 关闭旧侧栏后重新打开。确认顶部显示鲁班、当前网站；底部是聊天输入，原来常驻的策略/质量/执行表单已收起。
3. 使用已授权普通网页和现有模型配置。推荐本地夹具作流程验证，再用豆瓣/商品页验证真实效果；确保本地服务保持运行。
4. 先选不重要的测试工具。不要删除正式工具、撤销正式权限或清理正式数据库。
5. 记录 Chrome 版本、页面 URL、测试工具名称及是否通过；失败保留提示与脱敏截图。不要归档 API Key、认证头或含认证信息的 HAR。

**总准出：** 以下 C01–C14 全部通过；失败不能覆盖原草稿/保存版；生成不自动运行或保存。自动测试通过不能替代真实页面效果验收。原 R1 [O01–O16 清单](./v2.1-manual-checklist.md)中适用的数据/权限/运行保护继续有效。

## 1. 固定输入与滚动（C01、C05）

- [ ] 将侧栏宽度收至约 320px，正常宽度再验证一次。进行数轮对话，展开较长 Markdown 说明。
- [ ] 只有对话区滚动；顶部快捷操作、底部输入和已有制品栏保持可见，按钮不重叠，页面无横向溢出。
- [ ] 在底部等待新内容时自动跟随；向上翻看旧消息后，新内容不把位置抢回底部。
- [ ] 点击「↓ 回到最新」回到底部并恢复跟随。打开/关闭代码浮层后聊天位置保持。

**通过标准：** 无论对话多长都可继续输入和发送；旧消息可稳定阅读。

## 2. 输入、停止与保留（C02）

1. 输入两行文字：Shift+Enter 应换行。中文输入法组合候选时按 Enter 只确认候选，不能提交。
2. 完成输入后按 Enter，或点击右下角发送箭头。
3. 生成中输入下一条需求，不点击停止，等待本轮结束。
4. 再开始一轮，生成中输入新文字，点击停止按钮。

- [ ] 同时最多一个生成会话，连续点击不能重复调用。
- [ ] 生成中允许编辑下一条输入；本轮结束后这些文字仍在输入框，不自动提交。
- [ ] 点击停止后保留新输入与原有效脚本；迟到响应不替换草稿。后续可主动重新发送。

**通过标准：** 输入法不误发送；下一条未提交文字不丢失；停止动作不运行、不保存。

## 3. 直接发送与连续对话（C08、C10）

1. 新建测试工具，输入「把页面标题文字变红，重复执行不叠加样式」。点击发送。
2. 点击一次发送后直接出现生成过程，不应出现「确认本次发送范围」或「确认发送并生成」。首次发送同样如此。
3. 等待制品出现；生成不会改变网页。点击制品栏「运行」，观察实际页面。
4. 不满意时直接在底部输入「颜色再淡一点，保持其他功能」，发送。
5. 修改合适后点击运行；确认效果，再点击「效果符合，保存」。

- [ ] 简单任务无需填策略表。首次与后续对话均一键发送，不要求额外确认发送。
- [ ] 可主动点击输入框上方「发送范围」预览，预览本身不请求模型。
- [ ] 生成过程只有一条助手过程消息持续更新；完成后显示说明和一个当前制品栏，不常驻长代码/JSON。
- [ ] 保存前必须成功试运行并人工确认效果；生成不会改动旧保存版，失败保留旧有效脚本。
- [ ] 关闭重开工具后保留对话，继续修改仍归属同一工具。另开工具 B 不混入 A 的需求、引用或约束。

**通过标准：** 主要链路为「发送 → 制品 → 运行 → 效果符合保存」，无重复表单；真实效果不以“无错误”代替。

## 4. 过程、Markdown 与安全（C03、C04）

1. 正常生成时展开过程摘要；有基础错误修复时观察标题。检查/修复结果可在制品浮层「更多操作与诊断」中查看。
2. 查看带标题、列表、引用、粗体、行内代码、代码块和链接的说明；可要求模型用 Markdown 解释改动。
3. 如说明含 `<img ...>`、HTML 或危险协议链接，应只显示文字或不可点击标签。

- [ ] 展示实际处理状态和修改说明，不伪造逐字思维过程或把处理中视作成功；修复最多一次。
- [ ] 流式说明在同一消息内变化，不刷出大量气泡；不完整 Markdown 仍可阅读，不破坏输入布局。
- [ ] 代码块可辨认关键词/字符串；原始 HTML 不执行，外部图片不自动加载；安全 HTTP(S) 链接可打开。

**通过标准：** 过程可理解，说明可读，不执行模型生成的页面标记。

## 5. 制品浮层与手动编辑（C06、C07）

1. 点击制品名称打开代码浮层。核对当前脚本、行号、高亮；复制代码并粘贴到临时文本确认完整。
2. 已有保存版/上一版时切换版本预览，不能误把旧版显示为当前草稿。
3. 点击「编辑代码」，修改任意内容。此时点击关闭或按 Esc。
4. 应提示先保留或放弃编辑。选择「保留为未验证草稿」，再关闭。

- [ ] 浮层默认不打开；关闭后回到原聊天位置，焦点返回可操作位置。
- [ ] 编辑时未处理的修改不会静默丢失；放弃只放弃本次浮层编辑。
- [ ] 保留编辑不会联网、运行或保存；旧检查/运行凭证失效。必须重新检查并试运行，才有保存资格。
- [ ] 名称在浮层修改；保存时为空会被阻止，正常任务已有默认名称无需额外填写表单。

**通过标准：** 代码操作集中在浮层，手改后的内容明确为未验证草稿。

## 6. 选行添加到聊天（C13、C14）

1. 打开代码浮层，单击一行；再次单击取消。Shift+点击另一行选择范围。
2. 用 Tab 聚焦代码行，Enter/空格切换，Shift 配合选择范围；试选非连续行。
3. 点击「添加到聊天」。已有引用时按钮应显示「替换聊天引用」。
4. 核对底部引用标签、展开后的 `L行号: 原代码` 快照。输入修改要求后发送。
5. 再添加引用，修改代码/生成新版后尝试发送该旧引用。另从上一保存版添加引用也验证一次。

- [ ] 未选行时按钮禁用；清除和切换版本会清空尚未添加的选择。
- [ ] 添加后关闭浮层并聚焦输入；不自动发送、不填充修改意图、不改代码。单纯添加/移除引用不改变有效试运行保存资格。
- [ ] 非连续行范围显示准确；引用包含来源名称、版本身份、行号与快照；可展开、移除、明确替换。
- [ ] 单次最多 200 行、32 KiB；超限给出提示并保留选择，不截断发送。
- [ ] 发送详情中含本轮引用；发送后对话记录可展开查看引用，成功后输入区的待发送引用清空。
- [ ] 旧版引用标记「历史快照」，发送时被阻止并提示移除/重新选行；不请求模型、不按旧行号修改新版。
- [ ] 关闭重开工作区，未发送引用仍在；切换不同工具不会携带错误引用。

**通过标准：** 可以精确指出修改位置，来源可追溯；旧快照不误绑定到新版。

## 7. 复杂目标与快捷操作（C09、C11）

1. 在广告/推荐场景用底部「点选元素」。展开「当前页面/已点选元素」范围入口。
2. 核对候选，选最小完整模块，预览范围，确认策略再发送；不把正文/相邻模块当作隐藏目标。
3. 试运行后若标签/空白仍在，使用反馈快捷项或直接描述问题继续修改。
4. 改变模型/端点或修复策略后，再次发送仍直接生成，不增加确认发送。复杂目标的策略确认、授权与过时目标校验继续保留。
5. 顶部「分析此页面」须设置中启用；点击后先确认实际发送，再返回建议。选择建议只填入输入，不自动生成。

- [ ] 简单任务不被复杂策略阻挡；复杂范围或模型澄清在聊天内可见，可补充后继续。
- [ ] 目标变化会清除旧运行/保存资格；刷新页面后过时目标提示重新点选。
- [ ] 设置、分析、点选、制品运行/保存位置稳定；未生成时没有空制品栏。
- [ ] 分析中输入下一条文字，完成/停止后仍保留；离线、网站不匹配或忙碌时不能误操作。

**通过标准：** 目标范围明确且不静默扩大；快捷操作状态与实际能力一致。

## 8. 核心回归（C12）

- [ ] 保存 A → 修改并保存 B → 在浮层恢复 A：current/previous 正确轮换，GM 数据和对话保留。
- [ ] GM get/set/delete、null、工具隔离仍正常；生成的 GM 权限与代码一致，缺失授权不得绕过。
- [ ] 开启自动运行，在新开匹配网站生效；停用后刷新不再自动执行；SW 唤醒/重载恢复已有注册。
- [ ] 有草稿时导出仍仅导出保存版，并明确提示；不能混入待保存代码。
- [ ] 模型超时、限流、截断、错误代码均保留原版本，不自动反复请求；改代码/权限/范围后旧凭证无效。
- [ ] P7 自定义端点授权、拒绝授权配置保护、分析开关与 Key 隐私保持正常。

**通过标准：** R2 改造没有破坏 R1 的质量/预算/CAS/权限保护和 V2 已验收核心能力。
