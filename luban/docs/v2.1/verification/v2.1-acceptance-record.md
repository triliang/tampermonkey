## 1. 实现交付

- Acorn + eslint-scope + 版本化环境能力清单，识别未定义变量、正常作用域与 typeof；GM 使用 AST 实际引用，不扫描注释和字符串来推断授权。
- SSE 保留停止原因、DONE/EOF 和畸形事件；明确 length 不写有效草稿。
- V2.1 生成与修复统一预算，格式与代码修复共用一次追加机会；AI Client 在此链路关闭超时自动重发。实际 provider fetch 起始回调用于生产请求计数，测试 transport 明确使用替身计数。
- 裸未定义表达式移除可静态确认后接受；一般重写不能保证语义等价，修复范围不明时保留为待确认候选。
- meta 工作流辅助记录与工作区 CAS 同事务；失败候选与有效草稿隔离，最近会话精简审计最多保留 20 条，候选/辅助数据纳入容量守卫。
- 目标、有限祖先/相邻摘要、指纹与只读 overlay；目标和策略绑定文档；内容/模块选择、触发方式和保留约束明确展示。
- 结构化效果反馈进入原工具上下文，已确认约束不随对话裁剪丢失。模型提出约束/目标/触发歧义时先显示澄清问题，不写空代码或自动再请求。
- 正式 UI 拆出目标、质量、执行卡及状态投影；代码和权限折叠，主操作按阶段切换，新增“效果符合，保存”和反馈快捷项。
- 试运行凭证包含工作流和目标信息；比较脚本执行后的目标指纹，避免合法修改目标后无法保存。代码/权限修改立即清除旧检查与保存资格。
- 同工作区共享互斥锁覆盖生成、试运行、保存、恢复；原版本、GM、自动注册和标准导出仍走既有服务。

## 4. 与设计/原型的实现边界

- 不复制原型的关键词自动扩范围。用户选择候选/触发方式后确认策略；模型可返回结构化澄清。自然语言冲突识别依赖模型，不能保证识别任意语义冲突。
- 目标模块不是通用广告分类器；缺少可靠范围时重新点选。不存在可靠候选时不自动选择 body/整个侧栏。
- 自动修复对可证明的局部变更保守放行；更复杂的语法或逻辑修复可能要求显式复制候选并检查/试运行，这是范围保护而非伪报自动成功。
- 手改代码的修复通过明确“查看修复发送内容”入口，单次确认最多一次请求；键入不联网。
- 状态控制器投影复用现有 UI 状态，后台锁、revision 和会话归属承担一致性，未引入通用状态机库。
- 目标句柄不持久保存，页面重载后需要重新点选。脚本删除目标后的保存仍依赖有效执行、页面身份和人工确认，不承诺自动视觉检查。
- 会话记录保存最终已知请求数与结论。SW 突然中断时只恢复 interrupted，不推算尚未归档的请求/费用，不自动续发。
- 没有新增策略模型分析请求；P7 主动分析仍是独立入口。辅助信息 32 KiB、诊断 20 条、祖先/相邻层级等按技术方案建议采用。
