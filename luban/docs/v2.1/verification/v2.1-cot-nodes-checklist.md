# 推理节点展开/收起验收

日期：2026-10-15。本轮仅调整模型返回推理内容的呈现，不新增模型调用、不改变生成/修复预算或运行保存规则。

## 操作与标准

1. 重载 `luban/dist`，重开侧栏，保持「推理」开启后生成任务。模型须实际返回推理字段才有可展示节点；未返回时不补造推理过程。
2. 展开「推理过程 · N 个节点」。确认每个节点有序号、标题、时间线连接，节点内容可独立展开/收起。
3. 生成时观察新增节点。默认展开最新节点，先前节点默认折叠；手动展开旧节点后，新内容到来不应强行收起该节点。
4. 点击「展开全部」「收起全部」。结果应分别覆盖当前所有节点；后续更新遵循此手动选择。
5. 手动收起整个推理区，等待新内容或完成；不得自动抢开。手动打开或操作节点后，完成时不得强制折叠整个区域。
6. 触发一次受控修复时，首次请求和修复请求分别分组，不混成一条推理文本。
7. 重新打开有推理历史的工具，确认仍按节点显示；仅有正文或历史推理未保存时显示真实状态，不编造节点。

**通过标准：** 单节点、全部节点、整个推理区均可控制；可用 Tab/Enter 操作原生 summary/button；长内容保持区域滚动，底部输入可见。Markdown 和高亮沿用安全渲染，原始 HTML 不执行。

## 拆分规则

- 优先以原文 Markdown 标题、编号步骤划分；没有此结构时以段落划分。
- 代码围栏内的标题/空行不拆开；长标题仅在节点标题处缩短，展开保留对应完整内容。
- 每个请求最多 64 个展示节点，多出的段落合并进末节点，不额外丢弃原文；既有每请求 64 KiB 推理展示限制继续有效。
- 标题来自原文开头，不另行调用模型生成摘要、猜测步骤或把推理节点当作执行成功证明。
