# 推理模式验收

日期：2026-10-15。范围：脚本生成、一次受控修复、页面分析；默认开启，可手动取消。推理开关控制模型请求，不代表展示模型内部逐字推理。

## 1. 默认与关闭

1. 重新加载最新 `luban/dist`，刷新目标网页，关闭重开侧栏。
2. 首次使用新设置字段时，输入框上方「推理」默认勾选。
3. 取消勾选，关闭重开侧栏；打开 AI 设置页查看「启用推理模式」。
4. 在 AI 设置页重新启用并保存，已打开侧栏应同步显示开启。

- [ ] 旧配置没有此字段时自动开启；已明确关闭的设置不被重开覆盖。
- [ ] 底部取消立即持久化，不需要另点保存；设置页更改仍使用该页「保存设置」。
- [ ] 开关只改推理设置，不调用模型，不改 API Key、端点、工具代码或已有运行资格。
- [ ] 生成/分析中本地开关禁用；下一轮可切换。设置正在保存时不能误提交旧模式。

## 2. MiMo 实际请求

1. 使用已有 MiMo 配置，在扩展 **SW DevTools → Network** 查看请求；不要导出含认证头的 HAR。
2. 推理开启时发送简单需求，检查 `/chat/completions` 的请求体。
3. 关闭推理后再次发送。

- [ ] 开启：`thinking: {"type":"enabled"}`。
- [ ] 关闭：`thinking: {"type":"disabled"}`。
- [ ] 首次与后续生成都跟随设置，继续一键发送，不增加确认弹窗。
- [ ] 收到 `reasoning_content` 时显示“模型正在推理”；正文开始后正常展示修改说明。
- [ ] 最终草稿仅由正文 JSON 解析；推理文本不拼入代码、对话正文或实际请求历史；成功结果作为独立本地对话附件保留，展示规则见 [推理过程清单](./v2.1-reasoning-display-checklist.md)。

## 3. 修复与分析

1. 用受控错误场景触发一次基础修复，观察两次请求。
2. 启用「分析此页」，准备预览并确认分析；分别开启/关闭推理验证。
3. 主动打开发送范围后，在设置页改变推理选项，再尝试发送旧预览。

- [ ] 首次生成和修复使用同一冻结的推理模式；仍最多两次请求，修复关闭时最多一次。
- [ ] 页面分析也跟随开关；建议选择不自动生成、运行或保存。
- [ ] 旧预览在推理/协议变更后拒绝或被清除，须重新准备；生成期间配置变化不采纳旧候选。
- [ ] 推理模式仍保留取消、超时、截断、限流、检查、CAS 和效果确认保护；不会自动降级重发。

连接测试为轻量 ping，支持该参数的端点明确关闭推理；它不用于证明推理能力。

## 4. 自定义兼容端点

AI 设置 → 自定义端点 →「推理参数协议」：

| 选项 | 行为 |
|---|---|
| 自动识别 | MiMo 域名及 `api.deepseek.com` 使用 `thinking.type`；未知端点不传供应商参数 |
| thinking.type | 用于支持此协议的自定义服务/代理，开关分别发送 enabled/disabled |
| 不发送参数 | 使用服务端默认；不能保证服务端开启或关闭推理 |

- [ ] 已识别端点/显式 thinking.type 协议的开启、关闭参数正确。
- [ ] 未识别端点不会强行附带不支持的参数；发送详情显示“端点使用服务端默认”。
- [ ] 不匹配协议返回错误时保留原稿，不自动重试另一种协议。按服务商文档选择协议；当前不支持任意供应商字段映射。
- [ ] 更改协议仍遵守原端点授权和 Key 隔离规则。
