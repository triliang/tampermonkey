# 鲁班 V2.1 优化需求：以对话完成网页工具

修订：R2，2026-10-15。状态：交互需求与原型修订，正式扩展尚未按 R2 改造。R1 的工程检查结果不代表本次新交互已实现或通过验收。

依据：用户初步体验后反馈流程仍复杂，并要求固定底部 chat 输入、浮层代码制品、滚动生成过程/Markdown、集中快捷操作。保留 [R1 需求](./v2.1-optimization-requirements-r1.md)、[R1 原型](./demo-v2.1-r1.html)与原实施记录用于追踪。

## 1. 本轮设计结论

**让用户只需要描述、观察、继续说；脚本和技术状态退到需要时再展开。**

R1 叠加了目标卡、策略卡、约束表单、代码区、质量卡和保存区。虽然每项都有作用，常驻展示仍让用户承担过多流程判断。R2 将这些能力收进聊天主线和制品浮层，不删除后台质量保护。

| 用户要求 | R2 设计 |
|---|---|
| chat 输入框始终在底部 | 侧栏固定底部 composer；对话单独滚动，生成期间可停止 |
| 脚本作为制品 | 最新脚本放在输入框上方的紧凑制品栏；点击打开代码浮层，正文不常驻聊天页 |
| 生成过程向上滚动、支持 MD | 用户消息、处理摘要、生成解释和错误都进入同一对话流，支持安全 Markdown |
| 思维链展示 | 提供可折叠的思考摘要、处理步骤和状态；不声称展示完整内部推理，不混入未完成代码 |
| 快捷操作位置合理 | 顶部：分析页面、设置；输入区：点选、上下文；制品栏：查看、运行、保存；更多操作收进浮层 |

## 2. 范围与保持不变的规则

本轮改变交互编排，不重新实现版本仓储、GM 或自动注册。R1 的基础检查、一次受控修复、CAS、取消/迟到保护、准确主机、current/previous、失败候选隔离等规则继续适用。

简化不是把生成、执行和保存合并成一个自动操作：

- 发送需求后可生成，生成前有清晰的数据范围与费用说明。
- 检查通过后，用户点击运行才修改页面。
- 用户观察后点击“效果符合，保存”，才更新保存版。
- 草稿始终不自动运行；开启同站自动运行仍需用户明确操作及授权。

不新增自动执行代理、自动视觉验收、无限修复、截图上传、跨站操作或完整 IDE。P6 延期项仍独立保留。

## 3. 侧栏信息架构

侧栏采用固定头部、可滚动消息区、紧凑制品栏、固定底部输入区。侧栏本身不随消息整体滚动；窄侧栏不出现多个独立的常驻表单。

| 区域 | 内容 | 展示规则 |
|---|---|---|
| 顶部 | 鲁班、当前工具/网站、分析此页、设置 | 始终可达；图标有文本名称和提示 |
| 消息区 | 用户需求、澄清问题、处理摘要、Markdown 回复、运行反馈 | 唯一主要滚动区；原先常驻策略/质量卡不再单独堆叠 |
| 制品栏 | 最新脚本名称、草稿/保存状态、查看、运行、保存 | 有有效脚本才出现；只显示一个当前制品 |
| 输入区 | 多行输入、点选入口、目标/采集范围、发送或停止 | 始终位于侧栏底部，留出正常输入空间 |
| 按需浮层 | 代码、诊断、权限、发送详情、版本/设置 | 用户主动打开；关闭回到原聊天位置 |

首次空状态提供一句引导及少量可点击示例，不显示空代码框、空质量卡和不可用保存表单。示例点击填入输入框，不直接请求。

## 4. Chat 输入与对话

### 4.1 固定输入区

- 输入框与发送操作固定在底部。文本增长到合理高度后内部滚动，不能把消息区完全挤走。
- Enter 发送，Shift+Enter 换行；输入法组合输入期间 Enter 不发送。
- 生成中“发送”切换为“停止”，保留未发送的新输入。停止不承诺撤销已发生的页面副作用。
- 空白、离线、页面不支持或缺少配置时不能提交，附近说明原因并给恢复入口。
- 点选结果以输入上方的一个上下文标签展示；可查看、更换、清除。不要再同时展示多张目标摘要卡。
- 默认发送当前需求和有限页面摘要。点击发送即准备上下文并直接生成，首次或模型/端点变化也不再出现“确认发送”步骤。输入区保留按需查看发送范围的入口，主动查看不请求模型。
- 代码修复的追加额度仍在可见说明中体现；用户可以在设置/更多中关闭。更广页面范围、权限或供应商变化不能沿用旧告知。

### 4.2 多轮修改

用户直接输入“标签还在”“仍有空白”“只保留标题”，当前工具代码、有效约束及必要历史作为下一轮基线。反馈不要求先点击单独“继续反馈”才能输入。

运行后的消息可提供少量相关快捷反馈；点击只填入输入框，保持焦点，不自动发请求。每轮修改仍更新同一工具，A/B 工具不串联。

### 4.3 澄清与策略

简单任务直接进入生成，不先展示策略表。真正存在目标、触发或保留范围歧义时，在聊天中问一个简短问题，并给少量可选项或引导重新点选。

例如：“只隐藏图片，还是包括广告标签和留白？”用户点击“完整广告模块”或自然语言回复后，合并为本轮策略。范围可用只读高亮预览；不能根据一句“空白还在”静默扩大到整个侧栏。

用户已确认且范围未变时不重复询问。复杂任务的触发方式仍须明确，但不把触发下拉框默认常驻给所有用户。

## 5. 生成过程与 Markdown

### 5.1 同一消息内流式展示

生成时创建一条助手消息，显示“正在理解需求/生成脚本/检查/修复”等真实阶段。阶段更新在原消息内完成，不为每个 token 或阶段新增独立聊天气泡。

处理摘要默认折叠，标题展示当前状态；展开可看到简短步骤，如“确认广告模块范围 → 保留相邻推荐 → 生成脚本 → 基础检查”。展示的是可核对摘要与系统处理状态，不是模型内部逐字推理或执行成功证明。

结束后展示简短 Markdown 解释及制品入口；代码移至浮层。默认不在消息流展开长代码、诊断堆栈和原始 JSON。

### 5.2 滚动规则

用户在底部时，消息增长保持跟随；用户上滚阅读时停止自动跳动，提供“回到最新”。打开/关闭代码浮层不丢失聊天滚动位置。

### 5.3 Markdown 范围

支持段落、标题、列表、粗体、行内代码、引用、代码块和安全链接。代码块做语法高亮；未完成 Markdown 不破坏页面布局。

禁用原始 HTML 和脚本执行；外部图片不自动加载，危险协议链接拒绝。消息文字、代码与诊断作为不可信输入处理。Markdown 支持不意味着模型输出可以创建任意按钮或执行命令。

## 6. 脚本制品与代码浮层

### 6.1 紧凑制品栏

有有效候选时在输入框上方出现一条制品栏：脚本名称、版本/状态、查看代码、运行、保存。名称可由模型建议，保存时不能为空；改名放在浮层，不额外强制打开命名表单。

只有一个当前制品栏。历史消息可以保留版本说明入口，但不重复显示多组“运行/保存”按钮。失败候选不能冒充当前有效制品。

### 6.2 浮层

点击脚本名称或代码图标打开浮层。桌面呈宽抽屉/浮层，窄窗口为全屏或近全屏；保持侧栏中的输入和消息位置。

浮层提供：标题、草稿/保存版本标识、语法高亮、行号、复制、按需编辑、错误定位。编辑是可选模式，不要求用户懂代码才能完成任务。

权限、保存版/上一版、恢复、导出、自动运行和诊断收在浮层的次级区域。原本常驻的全部 GM 勾选项不再占据聊天页。

手改后明确标记未验证，旧检查与运行凭证失效。关闭浮层保留已确认的本地编辑；未提交的编辑需明确保留/放弃，不静默丢失。

### 6.3 操作规则

| 操作 | 可用条件 | 反馈 |
|---|---|---|
| 查看代码 | 有脚本制品 | 打开浮层，不运行 |
| 运行 | 当前页匹配、有效草稿通过检查 | 结果进入对话，制品状态更新 |
| 效果符合，保存 | 当前版本有效试运行完成、用户确认 | 保存更新，不自动开启运行 |
| 修改代码 | 浮层中明确进入编辑 | 标记未验证，不自动联网 |
| 恢复/导出/自动运行 | 有适用保存版本 | 保留现有版本、授权及导出保护 |

### 6.4 代码选行 → 添加到聊天

代码预览提供逻辑行号与选择高亮：点击切换单行选择，可累积选择多行，Shift 连选一个范围；Tab 到行后用 Enter/空格切换。换行显示不改变原始代码行号。

选中后显示行数和“添加到聊天”（Add to chat），未选择时禁用。添加后关闭浮层、聚焦底部 chat 输入，显示紧凑引用标签，例如“价格高亮 · v2 · L2–L4”；不自动填写修改意图、不自动发送、不改动代码或保存资格。

引用包含工具/制品身份、来源版本、代码快照与准确行号。非连续行明确列出范围；用户可查看全文或移除引用。已有引用时再次添加应明确替换，不静默合并不相关版本。

发送时将引用与用户要求一并作为本轮上下文，在对话中保留可展开的引用记录。原代码变化后引用仍是原版本快照，必须标记历史来源；不能把旧行号直接当作新版代码的同一位置进行覆盖。正式实现应以代码 hash/工作区身份核对，过时或跨工具引用需要重新定位或确认。

代码编辑中先保留/放弃编辑，再选择预览行；版本切换或代码内容变化清除未提交的行选择。引用代码仍属于发送预览和预算范围，不能自动附带更多页面数据或密钥。

## 7. 快捷操作布局

| 位置 | 操作 | 理由 |
|---|---|---|
| 顶部右侧 | 分析此页、设置 | 全局工具，避免挤占输入和脚本操作 |
| 输入区左下 | 点选元素、上下文详情 | 与本次需求的输入对象相关 |
| 输入区右下 | 发送 / 停止 | 始终只有一个提交或中止入口 |
| 制品栏 | 打开代码、运行、效果符合保存 | 与当前脚本状态绑定 |
| 助手消息下方 | 采纳建议、少量反馈快捷项 | 只在该结果相关时出现，不常驻工具面板 |
| 代码浮层次级区 | 名称、权限、恢复、导出、自动运行、详细诊断 | 低频操作按需展开 |

分析此页仍主动触发，返回建议进入聊天。点击建议只填入输入框，不直接生成或执行。设置中的真实端点/Key 沿用现有规则，不把 Key 放进聊天。

## 8. 质量、错误与保存保护

沿用 R1 的语法/作用域/GM/安全检查和一次修复预算。生成、检查、执行、效果、保存仍是不同事实，只改变呈现方式。

- 自动修复中在原助手消息显示“修复 1/1”；失败后给简短解释和“查看诊断/重新描述”，不无限重试。
- 截断或未完成结果不能成为可运行制品。原制品保持不变，失败诊断按需查看。
- 修复可能改变范围时在聊天中询问，不自动接受未知语义变化。
- 限流、离线、超时都在聊天中说明恢复动作，原稿不丢失。
- 运行无异常时说“执行已完成，请检查效果”，不自动宣布目标完成。
- 只有用户点“效果符合，保存”才提交；手改/权限/目标/页面变化后旧资格失效。
- 关闭、停止、放弃草稿不会自动撤销页面效果或 GM 写入，需要时提示刷新。

## 9. 可访问性与移动/窄侧栏

输入区在约 320px 侧栏仍可用；操作区换行时不盖住输入。消息长代码/长链接换行，不撑宽页面。浮层支持 Esc 关闭、焦点锁定及返回触发入口。

图标按钮有可读名称，状态不只靠颜色区分。流式状态公告合并，避免逐字打断辅助技术。触屏/软键盘出现时输入框保持可达，具体浏览器适配需真实验收。

## 追加交互：左侧网页代码预览（2026-10-15）

制品默认在左侧网页区域打开宽版代码浮层，右侧聊天保持可输入；支持已有高亮、复制、编辑、选行添加到聊天。预览失败时回退侧栏。名称和高级管理操作仍在侧栏。C06/C07/C13/C14 的验收扩展见 [专项清单](./verification/v2.1-page-code-preview-checklist.md)。浮层编辑仍须保留/放弃，不执行展示代码、不绕过试运行与保存保护。

## 追加能力：推理模式（2026-10-15）

生成、修复与页面分析默认请求推理，可在底部快捷勾选或 AI 设置页关闭并持久化。每轮模式冻结，旧预览不能套用不同设置；继续保持一键发送和现有请求预算。界面展示推理状态与说明，不展示内部逐字推理。未知自定义端点须明确协议兼容边界，不能用开关冒充服务端支持。验收见 [专项清单](./verification/v2.1-thinking-manual-checklist.md)。

## 追加交互：展示模型推理过程（2026-10-15）

在独立可折叠区域展示供应商实际返回的推理文本，支持流式安全 Markdown、首次/修复分段及成功对话附件。生成时展开，完成收起，可随时查看；不伪造未返回过程，不混入脚本 JSON 或后续请求历史。原“仅展示处理状态”的规则以本条追加要求为准。验收见 [专项清单](./verification/v2.1-reasoning-display-checklist.md)。

## 推理呈现追加：节点式展开/收起（2026-10-15）

模型实际返回的推理内容按原文标题/步骤或段落分节点；首次请求与修复请求分组，支持单节点、全部节点和整个推理区展开/收起。流式默认展开最新节点，手动操作后保留用户选择，不强制抢开或完成后强制收起。不额外调用模型生成节点或编造步骤。验收见 [节点专项清单](./verification/v2.1-cot-nodes-checklist.md)。

## 追加优化：脚本上下文与管理页（2026-10-15）

聊天在已有制品或选中脚本时自动携带当前完整脚本，输入区显示文件标签、草稿/保存版来源，消息记录携带来源版本；选行引用是补充而非全文替代。优先当前草稿，不自动附加上一版，超过预算不截断。

脚本管理页改为独立列表，核心为查看/编辑、删除、自动运行开关，可查看/恢复上一版；不承载聊天、历史会话或草稿列表。管理页编辑保留当前未保存草稿，但更新保存版继续经过真实试运行与效果确认，不建立绕过权限/CAS/凭证的保存入口。验收见 [专项清单](./verification/v2.1-script-context-manager-checklist.md)。
