## 1. 执行约定

本计划为一个完整交付批次。用户开始执行后，按下述依赖连续完成实现、相关验证、修复和交付，不要求用户逐项回复“继续”、不以中间模块完成作为结束。任务编号用于追踪，不是多轮审批节点。

用户已授权按本计划执行。本轮实现与工程检查完成，真实环境部分仍按清单验收；下列任务规则作为执行与证据追踪依据。

- 沿用个人项目、本地 Markdown，不关联 LUCP 或上报度量。
- 先检查仓库指令、已有改动和依赖，保留用户未提交内容，不回滚无关变更。
- 复用现有工作区、CAS、试运行凭证、current/previous、GM、P4 注册协调和 P7 配置，不另建旁路。
- 原型仅为交互参考，不复制模拟检查、关键词判断或定时假响应到正式功能。
- 不自动发布、卸载扩展、清空正式数据或切换用户模型配置。真实请求只使用已授权的服务与脱敏范围，不隐性增加额度或权限。
- 信息不足时先推进不依赖该信息的工作；仅对实际阻塞请求必要信息，不能把缺少真实验收环境当成停止全部开发的理由。
- 最终如有不可取得的真实环境，交付全部可完成成果与准确的待验收清单，不能声称全量通过。

## 2. 本批次交付范围

一次完成 F1–F6：基础质量检查、一次受控修复、多轮效果反馈、有限目标上下文、复杂任务策略确认、简洁工作区与异常恢复。

包括正式实现、必要依赖及锁文件、自动测试、可加载 dist、V2.1 人工验收清单、综合验证记录、构建摘要及相关文档更新。

不包含：完整 IDE、无限自修复、自动视觉验收、跨站代理、截图上传、任意 iframe 穿透、正式发布。V2 的 Chrome 138、真实 1 MiB/40 MiB 验收仍单列，不由本次新增测试代替。

## 3. 默认实施参数与变更处理

为避免连续执行中反复询问非关键参数，先按技术方案建议实施，下列默认值属于本计划决策，不是既有实现事实。

| 项目 | 默认实施规则 |
|---|---|
| 一次自动修复 | 发送预览中默认勾选，可关闭；确认生成授权本次最多一次追加请求 |
| 生成真实请求数 | 关闭修复最多 1 次；开启最多 2 次；格式与代码修复共享追加额度 |
| 网络重试 | V2.1 生成/修复禁用底层自动超时重发，429/超时由用户主动重试 |
| 目标采集 | 1 个目标、最多 4 层祖先、每层最多 3 个相邻节点、每段最多 120 字；仍受原整体预算/deadline 限制 |
| 失败候选 | 每工作区保留最近一次，正文遵守现有 256 KiB 单版限制 |
| 辅助信息 | 每工作区目标/约束/诊断等辅助数据建议上限 32 KiB，诊断最多 20 项；纳入总量守卫 |
| DB | 复用版本 1 和 meta 前缀，不重建旧数据库 |
| 动态引用 | 分级提示；不能可靠判断时不宣称检查全面通过；运行与导出保持各自能力边界 |
| 策略模型辅助 | 不后台自动调用；确需调用时单独预览并确认，不新增默认开启的隐式分析 |

实现发现上述参数不可行时，记录原因、替代值、影响及对应验证；不得静默放宽隐私、权限、请求预算或数据保护条件。产品行为冲突以需求为准。

## 4. 连续执行任务

依赖主线：E00 → E01 → E02 → E03 → E04 → E05 → E06 → E07 → E08 → E09。可以提前编写后续测试夹具和文档，但所有合并后的状态仍须验证。

### E00：基线与保护

工作：读取适用仓库指令；记录 Git 状态、现有构建及依赖；执行工程四项；列出已有失败，区分原有与新增问题；记录当前能力而非假设全部缺失。

验收：

- 用户原有修改未被覆盖，工作目录和运行入口确认。
- 基线日志和源文件摘要可追踪；失败有明确归因，不以旧日志充当新检查。
- 当前正式数据不被测试夹具复用或清理。

产物：`verification/v2.1-baseline.md`、基线工程日志。

### E01：类型契约与工作流状态

工作：新增 V2.1 诊断/目标/策略/反馈/会话类型；明确业务状态与 UI 投影；为每种修改定义 envelope、目标确认、质量结果和凭证失效规则；统一请求 ID 与 revision 绑定。

验收：

- 按需求 O05/O13 建立事件转换表；非法事件不可跳到可保存状态。
- 生成/修复/试运行/保存不能在同工作区并发，SW 校验独立于 UI 禁用。
- 页面/代码/grants/范围/配置变化使相关旧结果失效，不删除有效草稿。
- 状态转换测试覆盖取消与迟到完成，不仅测试正常顺序。

产物：共享契约、工作流控制器骨架、转换测试。

### E02：基础质量检查与环境兼容

工作：将 eslint-scope 作为显式锁定运行依赖，与 Acorn 配合；实现统一 QualityReport、wrapper 行号映射、作用域与环境清单、AST GM 引用；接入手改检查、试运行前检查和保存前关键校验。

验收：

- O01/O02/O06：裸变量 n 执行前定位；局部/闭包/解构/正常浏览器引用不误判。
- typeof 特性探测、对象属性与真实引用区别正确，正常字符串和注释不触发 GM 缺失。
- 缺失 grant 提供用户确认入口，不静默增权；已有可运行别名不因导出限制全部误禁。
- 检查器无法处理的语法明确返回不支持，不降级为正则“通过”。
- 生产打包可加载分析器，无 Node 运行时依赖；记录体积和检查耗时。

产物：检查服务、规则表、纯函数测试和打包验证。

### E03：响应完整性与统一修复预算

工作：保留 SSE 停止原因和结束方式；改造 AI Client 请求策略；由 GenerationSession 管理首次、格式纠正和代码修复；增加修复差异/范围变化保护及阶段事件。

验收：

- O03/O04：length 明确截断；异常断流与正常 EOF 区分；完整兼容响应不会仅因缺少 finish_reason 被误拦。
- 关闭修复真实 HTTP 最多 1 次，开启最多 2 次；格式失败后代码失败不会产生第三次请求。
- HTTP 429、超时、断流均计入实际请求次数，禁止隐藏的底层重试。
- 安全拦截、权限缺失和截断不通过自动补括号或加权限伪修复。
- 修复出现目标/grants/触发变化或无法确认语义范围时需重新确认，不直接替换有效草稿。
- 取消后 Abort 和 late response 均不能写入；手动输入不触发网络请求。

产物：流解析/会话/传输改动，请求计数与异常集成测试。

### E04：持久化、失败候选与恢复

工作：在 meta 增加辅助记录，复用工作区 CAS 与事务；保存结构化反馈/有效约束/精简会话；失败候选与有效草稿隔离；补齐删除、丢弃、容量和 SW 中断清理。

验收：

- O05/O13：工作区与辅助记录同事务提交，冲突或事务失败不产生半更新。
- 修复失败、取消、容量不足时原草稿和保存版不丢失，失败候选可查看但非默认基线。
- 重启只恢复已持久事实，生成中转 interrupted，不自动发模型请求。
- 旧工具无需全量重写，旧字段缺失按默认值读取；删除不会遗留关联辅助正文。
- 新辅助数据纳入现有逻辑容量；测试不能宣称已完成真实 40 MiB 最终验收。

产物：仓储扩展、恢复及容量测试、数据兼容记录。

### E05：有限目标上下文与范围预览

工作：提取 target-context/range-preview；采集受限祖先与相邻摘要；构建目标指纹和候选；排除自身 overlay/UI；确认前验证唯一性与目标存活。

验收：

- O07/O09/O14：广告主体、标签、占位能识别为最小完整候选，相邻正文不包含在操作范围。
- 单元素与完整模块可预览，预览不改变业务布局或提前执行脚本。
- body/html、整个侧栏和包含无关正文的祖先不自动入选；目标不足明确要求重选。
- DOM 同文档变化、目标消失/变多时旧指纹失效；跨 iframe 不伪装为外层可捕获。
- 自身 UI 不被采集或操作；摘要与实际发送内容一致，仍遵守脱敏和预算。

产物：内容脚本模块、广告/标签/相邻区/iframe DOM 夹具及定位测试。

### E06：多轮反馈、约束与策略确认

工作：扩展 envelope，持续使用有效草稿/手改基线；加入有效约束、来源明确的错误/效果反馈；建立简单直达与歧义策略路径、策略指纹及复用/失效规则。

验收：

- O08/O10：简单改色不强制策略卡；歧义目标有简短范围确认，不靠单个关键词自动扩大范围。
- “空白还在/标签还在”能在原工具继续修正；从元素扩大模块时更新范围并重新确认。
- 模型策略辅助只在明确预览确认后请求，P7 分析此页保持独立。
- 核心代码、需求、有效约束不可静默裁剪；预算不足明确拒绝并保留原稿。
- A/B 工具的反馈、约束、错误和策略不串联；反馈快捷项只填输入，不自动发请求。

产物：策略/反馈服务及多轮 envelope 集成测试。

### E07：正式 UI 与效果保存

工作：按 Demo 信息顺序拆分现有 App，复用至设置页；实现目标、策略、对话、检查、修复、执行和反馈卡；“效果符合，保存”接入已有命名保存；扩展 receipt 绑定工作流信息。

验收：

- O11/O12/O15：每状态只有一个突出主操作；执行无错误显示待观察，不伪报效果验证。
- 点击效果符合保存提交当前试运行版本，无额外重复效果确认弹窗。
- 修改代码/权限/目标后旧资格失效；后台拒绝伪造布尔确认或旧凭证提交。
- 提取、延时、监控按可确认阶段提示，不能以初始化成功承诺全部完成。
- 取消保留输入和原草稿；恢复/自动运行/导出仍走现有服务。
- 窄侧栏无横向溢出；Tab/Shift+Tab/Esc、焦点返回和辅助状态公告正常。

产物：正式组件、控制器接入、UI 集成测试；不把 Demo 当功能实现。

### E08：综合自动验证与问题修复

工作：运行全量测试、typecheck、lint、build；执行真实生产模块组成的本地闭环、受影响生命周期/GM/CAS 检查；修复新增问题后重跑受影响检查，最后形成同一构建的验证结果。

验收：

- 工程四项全部通过，测试覆盖 O01–O16 中可自动验证的规则。
- 集成走通：生成 → 检查/修复 → 试运行 → 效果确认 → 保存 → 自动 → 恢复 → 导出。
- 夹具使用独立数据与测试配置，模型替身与真实服务证据明确区分。
- 不修改 runner/注册时保留原有回归；如实际改动相关路径，补跑受影响 P4 故障矩阵。
- 新构建更新源码/依赖/dist 摘要，不继续引用旧构建通过结论。

产物：`verification/evidence/v2.1-{test,typecheck,lint,build}.txt`、`v2.1-source-sha256.json`、集成证据。

## 6. 失败与返工规则

- 检查器兼容失败：记录具体语法，修复或明确不支持；不改成正则通行。
- 请求超过预算：修复编排与底层重试，再重跑次数/取消/异常矩阵。
- UI 状态与后台不一致：修复状态契约和 CAS，不仅改按钮文案。
- 豆瓣部分生效：保留原失败，检查目标范围/上下文/策略，不只换一个容易成功的广告。
- 修改 prompt：重跑十场景比较；修改自动注册或 runner：重跑受影响 P4 断点；不重复与变更无关的全部测试。
- 超出当前可访问环境的事项：明确阻塞范围、已有证据和最小人工步骤，不把全部工作停在一个待确认问题上。
