## 2. 每阶段固定规则

1. 开始时在阶段文档列出验收编号、条件、命令或观察方式。
2. 完成实现后逐项记录通过、失败、未执行或需人工验收，不将 mock 当真实模型/扩展环境验证。
3. 失败先修复，在文档记录原因与重验结果。遇外部条件缺失继续完成不依赖该条件的工作。
4. 阶段完成必须落 Markdown，不能只口头汇报。架构与实际实现不一致时回写技术方案说明。
5. S5 后再执行 S6，不能用第一轮相同结论代替复核。最终报告明确尚未通过的发布条件。

## 3. 全局门槛

- 普通聊天不自动生成或执行脚本；页面与保存权限不交给模型。
- 目标、方案与基线变化使相应确认失效；重复投递不重复创建生成/执行操作。
- 取消、重启和迟到结果不覆盖当前成果，未知执行不自动重放。
- 保留 V3 入口和数据；所有新增入口使用独立能力检查与加性协议。
- 框架/模型能力不满足时明确不可用，不静默退回脚本生成。

## 4. 自动与人工边界

可自动：SDK 无网络契约、SQLite/IDB 状态、工具权限、幂等冲突、模拟页面 DOM、UI 交互、打包与静态检查。

需真实环境：用户模型端点与凭据、已安装扩展的 Native Messaging 配对、真实网页识别质量、跨域权限、实际试运行视觉效果、macOS 安装注册和外部客户端回归。将尽量自动完成已具备条件的项目，其余逐项列明原因、步骤及预期，不按通过统计。
