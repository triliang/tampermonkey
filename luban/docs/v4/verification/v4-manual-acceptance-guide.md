日期：2026-10-18。原清单已追加本轮实测结果；自动结果见 [自动验收记录](./v4-auto-verification.md)。本轮沿用 Chrome 注册与模型配置，实际调用模型并重载现有扩展，未发送外部消息。详细证据见 [真实环境记录](./v4-real-acceptance-record.md)。

## 1. 准备

- 构建扩展：`npm --prefix luban run build`；在 Chrome 扩展管理页加载或重新加载 `luban/dist`。
- 构建 Harness：`npm --prefix luban/harness ci`、`npm --prefix luban/harness run build`。
- 使用 `luban/bridge/dist/luban-bridge-macos-arm64` 本地发布包，Node 为固定 v24.14.1。
- 如需安装或升级 Native Host，按发布包的 install-bridge.mjs 使用说明核对实际扩展 ID 和已注册路径；安装器拒绝静默覆盖现有注册。本轮沿用原注册，已重载扩展并实际连接；没有修改系统注册。
- 在鲁班设置中连接 Bridge，配置并确认所用模型及端点。V4 需要支持工具调用和结构化输出，不等于已有文本端点天然兼容。

## 3. 评审时明确的实现边界

- P0 以明确按钮授权为主；对当前唯一已确认方案，仅支持严格整句“按当前方案生成脚本”等表达直接授权。疑问句或含新增范围的句子继续澄清，不按关键词猜测。
- 主 Agent 仅开放 5 个领域工具；主机执行、自由委派、文件工具、长期记忆和技能目录均未开放。
- 生成 Job 单次结构化输出，失败或检查拒绝后由用户再次确认重试，不无限自动修复。
- 候选通过检查后进入既有脚本区试运行与保存；V4 聊天不拥有直接运行或保存接口。
- 页面采集为最多 800 个主文档结构节点、40 个候选；跨域 iframe 未读取，不承诺全站拦截或完整召回。
- 清除会话会使未保存的 V4 草稿失去原需求确认；已保存工具按原工具流程保留和运行。
