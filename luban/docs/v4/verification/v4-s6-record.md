| 编号 | 复核点 | 预期 |

## 复核方法

重新从调用边界、事务、取消闭包、线程历史、版本条件与存储保留检查实现，增加能捕获问题的测试后修复；不将 S5 通过简单复制为复核结论。

## 新发现与修复

1. 旧子进程取消后退出回调可能删除同会话新 Worker 的 Map 项：增加 entry 身份匹配，取消同步结束旧闭包；增加新旧 Worker 交错测试。
2. 服务层运行中重复消息原先只返回 busy：先执行请求指纹去重，返回已有运行；去重记录由整份会话改为小型结果引用，避免配额被历史放大。
3. 拒绝/取消待确认调用后旧 checkpoint 仍有中断：增加 checkpoint 代次，主动放弃旧分支，必要时从有限领域消息重建新分支；没有恢复执行权限。
4. 普通追问增加 run epoch 后，不应误使此前候选失效：制品按生成时的版本与操作身份验证，普通回答后保留候选状态。
5. 方案原来只绑定目标和动作：加入读取页面时的基线 hash，授权后代码变化即拒绝生成；提交时继续做基线比较。
6. 增加会话清理及 30 天维护，联动删除领域记录、请求去重与 checkpoint 文件，保留脚本工具。
7. UI 轮询可能晚于决定操作返回：以事件 sequence 拒绝旧快照覆盖。
8. 标注缺少元素尺寸变化通知：加入 ResizeObserver 并在清理时断开。
9. V4 提交原来可能继承旧 V3 目标 Workflow：提交新候选时重建该版工作流与约束，原草稿失败保护仍在事务中。
