## P1：隐藏整个页面仍会通过效果检查

位置：`src/content/annotations/registry.ts:37`。

复现：页面包含导航、正文和已确认广告；执行 `document.body.style.display='none'`。该代码通过现有 inspectCode 检查，广告因祖先隐藏而得到 hidden，残留扫描为空，最终 passed=true，但导航和正文同时不可见。

原因：验收只检查广告目标消失，没有检查计划要求保留的内容是否仍可见。

建议：绑定页面时记录导航、正文等保留区域的基线；效果验收同时检查目标隐藏和保留区域可见。保留区域消失时不得判定通过，并向 Chat 提供误伤证据。

验收标准：隐藏 body 或包含正文的共同祖先必须失败；只隐藏确认的广告容器且正文导航保持可见才能通过。

## P1：容器稳定指纹放宽后，失效确认仍可用于正常内容

位置：`src/content/annotations/registry.ts:18`、`:31`、`:39`。

复现：扫描含广告 iframe 的 `#kp_box_www_swiper`，随后将容器子内容替换成 `<main>新的正文内容</main>`，保持容器 ID 和 class 不变。resolve 仍成功返回原确认目标。

原因：该类容器的稳定指纹只包含 tag、ID 和 class，resolve 没有再次执行广告归属检查和 add 中的 main/article 等范围保护。后续生成或试运行可继续把正常内容当作已确认广告隐藏。

建议：允许轮播素材变化，但重新验证容器的广告归属和保护内容边界；广告证据消失或出现正文等保护区域时使确认失效，重新分析和确认。

验收标准：广告素材轮换仍有效；广告位被替换为正文或加入保护区域时必须返回 TARGET_STALE 或范围错误，且不能沿用确认执行。

## 待明确的验收语义

只选择一个广告、排除其他广告时，当前 check 仍把所有未处理广告计入 passed=false。临时用例已复现此行为，现有 dim 测试也明确包含该语义。建议区分“已确认计划执行成功”和“全页广告清理完成”，避免局部计划被误报为执行失败。此项暂不计为确定缺陷。
