## 2. 已实现的产品主链路

1. 网页侧栏直接使用升级后的原 Chat，历史与脚本操作在同一界面，无版本切换。
2. 发送时使用当前配置模型进行普通对话，首次发送自动配置 Native 模型连接；打开历史不调用模型。普通问答不自动读取页面或创建脚本。
3. 用户选择“授权并识别当前页”，对当前文档进行有界采集；候选引用进入领域状态，Agent 可按需读取证据与提出目标建议。
4. 用户排除误判、补选区域、定位并查看标注，分别确认目标与处理方案。
5. 需求说明保存目标、保留约束和待明确项；存在未解决问题时拒绝形成可生成方案。
6. 用户明确授权生成后，由有界 Job 调用配置模型产生候选；主 Agent 无直接执行、保存或主机命令能力。
7. 候选经过代码检查、基线比较、页面/目标复核与 IDB 幂等提交，才进入脚本区。
8. 用户在脚本区独立试运行，实际效果符合后保存。V4 不自动开启自动运行。

## 3. Deep Agents 落地方式

- 实际依赖：deepagents **1.15.1**、@langchain/core **1.2.18**、@langchain/langgraph **1.5.1**、@langchain/langgraph-checkpoint-sqlite **1.1.0**、@langchain/openai **1.6.2**，完整依赖以 Harness lockfile 为准。
- 主 Agent 仅开放 5 个领域工具：需求提议、页面证据读取、目标提议、方案提议、生成请求。
- 模型调用前工具过滤与派发边界双重拒绝 task、execute、write_file 等内置能力；虚拟文件后端读写默认全部拒绝。
- 使用真实 SqliteSaver/interrupt/Command；等待确认不持有浏览器执行权。取消/拒绝后以新的 checkpoint 代次继续，旧分支不自动重放。
- 生成 Job 为单次结构化模型调用，输出候选而非执行。配置密钥只驻留运行内存，不写领域库或检查点。
- 本轮未开放自由子代理、主机文件工具、长期记忆和动态技能目录。

架构图、边界与实现差异详见 [技术方案](./v4-technical-design.md)。
