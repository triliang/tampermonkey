# 实施与根因

真实 Chrome 现场确认已加载上轮侧栏变更，模型也只提议候选 22；并非模型将 40 个节点都判为广告。真正遗漏是 HarnessGateway.show 将全部 targets 传给页面，并将其余 39 个作为 excluded 绘制。结果导航、图片、分类等都出现“已排除”边框，造成大量广告场景的错觉。

## 修复

- Gateway 只发 selected 作为标注范围；无选择时调用 clear，避免沿用旧标注或退化成全量标注。
- TargetRegistry 兼容旧调用：收到 ids + excluded 时先过滤 excluded，只解析、监听、绘制有效所选范围。全排除时清除标注。
- 侧栏提示改为“已标注所选 N 处范围，未选结构节点不显示”，无选择时提示先分析。
- 不加入广告识别规则、站点域名/选择器或固定目标数量；保持真实编号及现有确认边界。

## 验收标准与自动结果

- 40 个结构候选中只选第 22 个：仅 1 个标注，编号 22，不绘制其他 39 个已排除框：通过。
- 全排除或没有选中范围：移除旧标注：通过。
- Gateway 只发送 selected；页面和工作区授权校验继续生效：通过。
- 目标相关定向回归 42 项通过。
- 全量扩展测试 62 文件、461 项通过；类型检查、ESLint、生产构建及 diff 空白检查通过。
