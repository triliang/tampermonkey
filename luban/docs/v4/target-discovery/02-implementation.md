# 实施与阶段验收

## 根因

页面采集返回的最多 40 个结构节点被直接展示为“页面目标”，且默认全部展开。结构证据与模型语义判断混在一个层级，用户被迫承担筛选工作。

## 修改

- 主卡片空状态为“页面已读取 · 等待目标分析”，不再用结构节点数量宣称目标数。
- 增加“根据当前需求分析目标 / 重新分析目标”，通过现有 controller.send → 模型配置 → Harness message → Deep Agents 工具链处理。
- 分析要求依据当前需求和真实证据提出目标、解释位置/依据/不确定性；需求未明确先澄清，证据不足说明缺口，不凑数。
- 主列表只呈现当前选中范围，保留真实候选编号与定位；图片 URL 不再占据主列表。
- 原始结构节点、技术覆盖详情和分页移入默认折叠的“手动补选 / 采集详情”。移除全选入口，标注和检查收进辅助区域。
- 分析不调用确认、生成、运行或保存；目标确认和原有授权流程继续独立。

## 验收标准

- 40 节点、0 选中：主列表为空，显示待分析，原始清单折叠。
- 多节点、1 选中：主列表只显示这一项；原编号不变；完整 URL 只在辅助详情。
- 点击分析：只发送模型消息，不调用确认/生成接口。
- 原有分页、定位、效果复核、会话恢复和授权边界回归通过。
