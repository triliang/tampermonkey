# 阶段 4：复核、修复与再验收

## 复核项目与结论

| 项目 | 结论与修复 | 自动验证 |
|---|---|---|
| 通用能力 | 无域名、选择器库或任务识别特判；当次选择器仅出现在合成制品/测试 | 通用边界脚本、人工代码复查 |
| 原会话与草稿 | 不新建产品聊天入口；模型切换沿用工作区、历史、输入和独立授权 | 统一聊天回归含执行方切换 |
| API Key | 本地分支不调用 API 凭据加载；API 切回保留设置 | 惰性配置加载测试 |
| 多会话 | 模型配置绑定 owner + conversation；拒绝跨 owner 配置 | Bridge 并发配置回归 |
| 工具边界 | 仅绑定工具可返回；参数须对象，Deep Agents schema + 域前置条件继续生效 | 未绑定工具/错误参数/批准中断与恢复反例 |
| 版本兼容 | 功能限制和 schema 能力探测代替构建号相等；本机 0.163.0-alpha.10.2 真实通过 | 新旧/后续模拟版本、缺字段/缺限制拒绝 |
| 进程与临时目录 | 第二轮发现强杀 worker 可能绕过 adapter finally；改由 Bridge 持有每轮目录并统一清理 | 真 worker + 嵌套模型进程取消测试，目录清理测试 |
| 错误分类 | 真实请求发现账号路由内部错误；只读账号检查最多 3 次，推理不自动重放；框架 MiddlewareError 包装丢 code，改为有界读取 cause | 包装认证/超时/协议/API 错误与循环 cause 测试 |
| 模型输出 | 使用完成消息替代中间流拼接；强制候选工具、数量及权限仍经候选 schema 校验 | final-message 测试、候选测试 |
| 制品门禁 | 真实 Codex 输出固化为离线 fixture，走原 HarnessGateway 基础检查/提交；无试运行回执、无已保存脚本 | 真实样本回归；不依赖运行网络生成证据 |
| 安装包 | 重新定位的包验证 Codex adapter 能找到内置 transport，PATH 无全局 Node 也可运行 | 打包烟测 |
| 设置文案 | 删除固定 CLI 版本承诺，解释兼容检查和 V4 原会话使用方式 | 构建/类型/lint |

## 失败记录与处理

- 初次本地 Bridge socket 测试受沙箱 EPERM 影响；在获准本机 IPC 环境中重跑通过。
- 初次真实模型在沙箱内无法启动 App Server；使用获准的本机子进程环境复测。
- 真实账号路由发现出现临时失败；保留首次失败和后续成功证据，不把失败归为生成质量问题。
- 新增真实制品样本测试首次路径错误（ENOENT）；随后发现扩展类型环境不含 Node fs。改用独立 JSON fixture 静态导入，最终类型、测试和构建均通过，不依赖可变的最新验收日志。
- 两次工具权限自动审核超时：一次真实复测、一次浏览器文档读取；按工具规则处理。真实模型重试后完整通过。已安装 Chrome 新版本 UI 尚未完成重新加载验收，明确保留边界。

最终验收批次及数量见 [阶段 3](./04-acceptance.md)，整体使用方式见 [报告](./06-report.md)。旧五站页面验收不计入本轮 Codex 后端证据。
