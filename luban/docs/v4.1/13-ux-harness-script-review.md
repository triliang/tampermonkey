# 界面、筛选精准度与脚本头评审

日期：2026-10-19。依据当前源码，覆盖 V4 侧栏、Harness 工具边界和用户脚本制品。本文只记录问题与改法，不改运行时。

依据：

- `src/sidepanel/App.tsx`、`src/sidepanel/v4/HarnessChat.tsx`
- `harness/src/runtime.ts`、`harness/src/worker.ts`
- `src/content/annotations/registry.ts`
- `src/service-worker/prompt-builder.ts`
- `src/service-worker/services/userscript-export.ts`

先改三处：把当前步骤钉在输入框上方；把整页倒出改成按需检视加选择复核；脚本头由产品按已确认的网站、权限和运行时机拼上，模型只写正文。

当前约束：领域工具 5 个，单轮模型调用上限 8 次，每批结构候选 40 个，用户脚本头只在导出时写入。

## 1. 界面

V4 侧栏把对话、目标、方案、候选和效果检查叠在同一条滚动里。主操作和解释抢位置。

| 严重度 | 问题 | 现在的表现 | 改法 |
| --- | --- | --- | --- |
| 高 | 操作区沉在对话下面 | `HarnessCards` 渲染在消息列表之后。侧栏里要先滚过聊天，才能确认目标、方案和生成。 | 把当前步骤钉在输入框上方。聊天只留模型解释，卡片不再跟消息一起滚走。 |
| 高 | 分析按钮冒充用户发言 | 「根据当前需求分析目标」把一整段系统指令交给 `send()`，写入用户消息。模型会把它当成用户意图。 | 按钮只触发一次工具轮次。指令留在系统侧，对话里显示「正在按当前需求筛选目标」。 |
| 高 | 同一目标两套勾选 | 已选列表和「手动补选」清单都能改 `selected`。上面的复选框恒为勾选，点一下是移除。 | 主界面只展示模型建议的短列表。结构清单默认折叠，补选结果合并进同一份选择。 |
| 高 | 确认路径分叉 | 「确认所选目标」之后还要再选隐藏或弱化；「确认所选并采用隐藏方案」直接跳过方案。 | 一步：核对范围，再选隐藏或弱化。去掉会直接改成隐藏的快捷按钮。 |
| 中 | 按钮没有层级 | 授权、补选、确认、生成、拒绝、检查、三色标注并排，同等样式。 | 每步只留一个主按钮。标注颜色、下一批、诊断收进次级菜单。 |
| 中 | 顶栏和底栏重复 | 顶栏 ✳ 在 V4 里同样调用 `scan`，和底栏「授权并识别当前页」是同一动作。 | 顶栏只保留页面、工具库、设置。识别页只留一处。 |
| 中 | 试运行反馈写死成广告话术 | 回执出现后固定给出「标签还在 / 仍有空白 / 隐藏范围太大」，暗色、提取列表也会看到。 | 反馈改成通用项：没生效、范围过大、误伤了要保留的内容，并带回对应目标编号。 |
| 中 | 状态全是否定句 | 每张卡片都在解释不会运行、不代表完成、未覆盖整页。窄侧栏里有效信息被挤掉。 | 用步骤条表示授权、筛选、确认、方案、草稿、运行、保存。限制只在当前步骤写一句。 |
| 低 | 候选代码不进制品对话框 | 候选是卡片里的 `pre`。应用到草稿会把 `view` 设成 `editor`，但界面只区分资料库和其余，`editor` 没有单独布局。 | 候选直接打开现有代码对话框，并显示即将写入的完整用户脚本。 |

优先顺序：钉住当前步骤，分析按钮不再写入用户消息，确认范围之后再选隐藏或弱化。

## 2. 筛选精准度

采集本身不判定业务。精准度卡在模型一次看到的证据太扁，而且没有复核工具。Deep Agents 继续只编排领域工具，不开放文件和命令。

模型实际拿到的是标签、300 字扁平文本、`id` / `class` / `role`、边界矩形、同批 `parentId`、iframe 个数。`reason` 对每个节点都是同一句「用途需结合需求判断」。

因此会偏：名额按 DOM 顺序先到先得，嵌套节点把 40 个名额占满。父容器经常不在本批。空文本大盒子、固定定位、兄弟重复都看不见。

调用预算最多 8 次。一次读全量再提议，几乎没有「检视、剔除、再提议」的余地。读取下一批还会撤销已确认目标。

| 能力 | 收益 | 落点 | 做什么 |
| --- | --- | --- | --- |
| `inspect_target` | 高 | 现在补上 | 对单个候选返回祖先链、兄弟摘要、子树文本量、链接数、图片面积、fixed/sticky、与视口相交比例、与其他候选的包含关系。`parentId` 只在同批 40 个里才有，父级经常是断的。 |
| `query_targets` | 高 | 替换现有读取 | `read_page_context` 目前无参数，一次倒出最多 40 个 DOM 序节点。改成按区域、最小面积、有无文本、标签查询，返回短索引；细节走 inspect。 |
| `review_selection` | 高 | 新增 | `propose_targets` 之后由领域层计算：嵌套双选、选择器不唯一、选中节点吞进大量未选正文。模型必须先处理这些异议，不能只用一段 reason 带过。 |
| 被拒绝候选回读 | 中 | 补字段 | 用户取消勾选只改 `selected`。下次读取应带上被拒绝的编号和可见特征，避免原样再提议。 |
| 短名单截图 | 中 | 可选 | 只对已短名单的少数区域截局部图，给支持视觉的模型。不要对整批 40 个截图。本地 Codex 路径需要单独确认是否吃图。 |
| 筛选复核子代理 | 中 | 编排 | Deep Agents 可以跑一个只读复核代理，工具仅限 query、inspect、review。它不能提议方案，不能请求生成。主代理必须回应它标出的无证据选择。 |
| 分析前计划 | 低 | 编排 | 内置待办可以强制先写下纳入标准和排除标准，再允许 `propose_targets`。文件系统、shell、通用 task 继续拒绝。 |

站点专用规则仍然不能写进工具或提示词。截图和子代理只提供证据与异议，不直接判定业务目标。

## 3. 脚本头

草稿和候选都不是 Tampermonkey 脚本。

- V4 生成提示词写明禁止用户脚本元数据头。
- 旧生成提示词要求的是「意图 / 生成时间」功能注释，并声明注释里的 `@grant` 无效。
- 侧栏候选展示的是 `artifact.code` 正文。
- `buildUserscript` 只在导出保存版时前置 `==UserScript==`。字段有 name、namespace、version、match、run-at、grant，没有 `@description`。适用规则未确认时导出直接拒绝。

从侧栏复制出去的代码，缺少 `@match`、`@run-at`、`@grant`。

对齐方式：头由产品写入，不交给模型。材料只用已确认的名称、host 对应的一条 `@match`、run-at、实际使用的 grant、一行 description。

```javascript
// ==UserScript==
// @name         工具名
// @namespace    https://luban.local/userscripts
// @version      时间戳.修订
// @description  一行说明
// @match        *://主机/*
// @run-at       document-end
// @grant        GM_addStyle
// ==/UserScript==
```

运行仍读取结构化 grants，不从注释解析权限，避免改注释提权。编辑器、候选和导出共用这一份；导出检测到已有合法头就不再拼第二份。模型继续禁止输出 `==UserScript==`、`@match`、`@grant`。
