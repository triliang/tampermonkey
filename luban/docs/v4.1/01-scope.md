# V4.1 需求范围与详细说明

日期：2026-10-19。性质：基于当前仓库与用户诉求的执行基线，用户可继续调整。V4.1 是产品迭代名，扩展/Bridge 协议版本独立。

## 背景与依据

依据：用户本轮四项诉求、`../v4/v4-iteration-complete-report.md`、`../v4/v4-generic-capabilities-report.md`、`../v4/target-discovery/cnblogs-annotations/04-review.md` 与 `../../AGENTS.md`。历史问题包括站点特判、结构候选全部标注、局部检查冒充完整目标、旧证据混用、Codex 协议与授权状态失效。

## 范围

1. 建立可执行红线，覆盖通用性、证据、目标身份、授权、保留区域、失败与结论边界。
2. 建立广告过滤、数据统计、普通聊天、动态替换、重复标识、注入与未知覆盖的验收场景。场景金标只属于测试。
3. 本地 HTML 合成夹具与生产目标注册器直接回归；每轮默认不启动 Chrome。需要布局、Native 配对或真实渲染时保留真实浏览器抽验。
4. 同一输入、同一输出协议、同一金标对比第三方与本地 Codex，记录原始输出摘要、版本、错误、延时和失败率；真实不可用必须标记未验证。
5. 按阶段保存需求、PRD、技术方案、执行、验收、复核、总报告。

## 不纳入本轮

不新增 CSDN 或任何站点适配器；不开发广告规则引擎；不把数据统计下沉为页面工具业务特判；不改变原 Chat 与生成/运行/保存授权流程；不以模拟模型冒充真实效果；不发布、不自动保存用户脚本、不开启自动运行。

## 产品行为

用户给出目标后先读取有界证据；模型提出范围和理由；用户确认；生成、运行、保存分别授权。只读统计需说明数据口径、有效行、去重、缺失、单位与覆盖，不需要修改页面。现有产品对任意统计任务的端到端支持不视为已完成，本轮先建立评估能力。

## 验收层级

L1 本地确定性：生产模块、HTML、金标、故障注入；L2 模型语义：固定题集对比；L3 系统集成：现有自动门禁；L4 Chrome/Native/真实模型端到端抽验。各层独立记录，不能相互替代。

## 已确认与限制

用户已确认“独立项目 / Luban / 仓库通用PRD”，不关联LUCP、不上报度量。第三方复用既有 MiMo mimo-v2.6-flash 配置，凭据仅在评估进程内使用，不归档。RTK.md 在仓库及已检查的上级位置未找到，暂执行 AGENTS.md 已知规则。
