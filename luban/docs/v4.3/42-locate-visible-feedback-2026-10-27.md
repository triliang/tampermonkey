# 范围列表与页面定位的可见对应

## 问题

原 locate 只滚动到目标，没有自动显示标记；用户在侧栏点定位后，很难在网页分辨对应区域。已有“显示标注”需要另点，且页面标签放在目标顶部之外，大容器或视口边缘可能看不到编号。

## 修改

- 定位前继续验证真实节点身份和唯一引用，然后滚动到目标、显示单个蓝色边框、淡蓝填充和轻微背景压暗。使用独立 Shadow DOM 覆盖层，不改目标样式或隐藏内容。
- 页面显示“候选 N · 正在定位”，沿用原始候选编号。标签位置限制在视口内，大容器顶部超出视口时仍能看到编号。
- 标注跟随原有滚动、尺寸和节点变化更新；切换候选只强调当前项，关闭标注移除覆盖层。启用减少动态效果时即时滚动。
- 侧栏定位成功后对应行浅蓝高亮，按钮显示“已定位”，并提供候选编号的无障碍名称。切回显示全部标注或关闭标注时清除侧栏定位状态。
- 定位不改变目标勾选、确认范围或任何生成/运行/保存授权。版本保持 0.4.3。

## 验证

界面底层新增回归：居中滚动、同编号标签、视口顶部裁剪、候选切换、目标原始样式不变、关闭清理。全量测试和构建记录于交付说明。

隔离真实 Chrome 验证定位标记、真实候选编号和清除行为，随后回归独立生成、运行、保存。见 [链路记录](evidence/2026-10-27/locate-highlight/native-dom.json) 与 [页面截图](evidence/2026-10-27/locate-highlight/located-target.png)。模型为本地协议夹具，未操作用户原业务页面。

本轮仅更新扩展前端；重新加载扩展并刷新目标网页后生效，不需要重启 Bridge。

最终结果：扩展全量 546 项通过；随后清理定位状态的小调整对应的定向回归通过，正式构建通过。隔离 Chrome 共 28 项检查通过，页面截图已目视检查，能直接看到蓝色区域边界与对应候选编号。
