# Luban v4.3 UI/UX 设计说明

日期：2026-10-20  
状态：设计评审草案；尚未实现、制作高保真原型或完成浏览器验证。  
依据：[需求范围](01-scope.md)、[产品需求](02-prd.md)。本文细化界面和交互，不扩展功能范围；尺寸与视觉数值均为待原型验证的设计建议，不代表既有规范。

## 一、设计目标与原则

用户在任意时刻应能回答：**正在处理哪一页、系统在做什么、是否需要我决定、当前脚本是什么版本。**

| 原则 | 设计规则 |
|---|---|
| 对话为主 | 用户表达意图，Agent 汇报发现与建议；内部工具流程不变成操作向导 |
| 信息各有归属 | 对话承载交流，过程承载证据，决策区承载授权，制品承载代码与版本 |
| 渐进披露 | 默认给结论与关键限制，证据、技术信息及高级参数按需展开 |
| 操作有明确对象 | 确认范围、授权生成、运行和保存分别命名，不使用含义模糊的“继续” |
| 视觉安静 | 用排版与留白建立层级，强调色集中在当前主要操作，避免卡片套卡片 |
| 状态可信 | 运行完成、检查通过、保存成功分别表达；无法判断时明确说明 |

范围限于现有隐藏、弱化与相关分析能力；不新增终端、多栏工作台、双队列、多主题、自动回滚或新的集成渠道。

## 二、信息架构与页面职责

| 视图 | 主内容 | 入口与返回 | 保留状态 |
|---|---|---|---|
| 对话 | 用户发言、Agent 结论、过程入口、制品摘要 | 默认主视图 | 草稿、阅读锚点、展开状态 |
| 范围核对 | 当前唯一目标集合、定位、选择、依据、保留要求 | 当前决策区“核对范围”；完成返回对话 | 目标身份及有效选择 |
| 脚本制品 | 完整代码、版本、适用规则、权限、运行记录 | 对话制品入口；返回来源位置 | 当前版本、阅读位置、未保存编辑 |
| 设置概览 | 模型服务与设备状态、已有外部入口 | 顶栏设置；返回来源视图 | 来源及未提交配置 |
| 服务/连接详情 | 当前对象相关配置和诊断 | 概览卡；返回概览 | 当前表单、测试对象与结果 |
| 工具库 | 既有工具管理能力 | 顶栏工具库；返回对话 | 延续既有规则，本版不重做工具库 |

范围核对和脚本制品是侧栏内的替换视图，不是额外浏览器页面。系统不自动弹开代码视图打断用户阅读；生成后提供明确入口。

### pi-web 参考如何落地

| scope 中的模式 | 本文落地位置 | 适配边界 |
|---|---|---|
| 消息分类、过程分层 | 第四节 | 不展示内部推理，不折叠授权和错误 |
| 文件独立查看 | 第六节 | 单列替换视图，不搬入横向多页签 |
| 忙碌时输入 | 第五节 | 保留草稿与停止，本版不要求执行中提交队列 |
| 阅读、草稿与版本恢复 | 第九节 | 恢复阅读不恢复旧授权 |
| 服务卡片到详情 | 第八节 | 参数按方式显示，不照搬桌面服务树 |
| 语义视觉变量、键盘交互 | 第十、十一节 | 不照搬桌面宽度和小字号，实际验证焦点 |

pi-web 的源码事实与行号仍以 scope 第八节为来源，以下均为 Luban 的设计建议。

## 三、侧栏框架与布局

### 3.1 对话主视图

```text
┌──────────────────────────────────┐
│ 当前页面摘要          工具库 设置 │ 顶栏
├──────────────────────────────────┤
│ 用户：需求与保留要求             │
│                                  │
│ › 分析过程 · 已完成               │ 可展开证据
│ Agent：发现、建议、不确定性        │
│                                  │
│ 脚本名称 · 当前版本 · 查看脚本 →   │ 生成后出现
│                                  │
│               查看最新 ↓          │ 仅阅读历史时
├──────────────────────────────────┤
│ 核对处理范围                     │ 当前决策，按需出现
│ 已建议的区域与处理方式摘要        │
│ [确认范围]   核对范围   取消       │
├──────────────────────────────────┤
│ 等待确认范围                     │ 紧凑任务状态
│ 输入目标或补充要求……             │ 输入区
│                           [发送] │
└──────────────────────────────────┘
```

示意内容不代表所有模块同时常驻。无待决策事项时完全移除决策区，不预留空白；普通聊天不显示页面改造流程。

### 3.2 高度与滚动

- 顶栏和输入区保持可达，主内容承担主要纵向滚动。
- 决策区只放摘要和操作；长目标列表进入范围核对视图，不在底部展开成半屏清单。
- 默认不对用户气泡、证据卡、目标行分别设置独立滚动；长消息用“展开全文”控制占用。
- 制品以代码阅读区为主要滚动区；行内容需要时允许横向滚动，页面整体不得横向溢出。
- 低高度或大字号下，优先保持输入和关键操作可达；必要时决策摘要随主内容滚动，输入区保留当前事项的跳转入口。
- 不通过压缩到过小字号、遮盖最后一条消息或叠加多层固定栏来维持布局。

### 3.3 响应式原则

始终单列。宽度不足时按钮换行、标签缩短、元信息移入详情；页面标题可省略显示但能查看完整名称。建议以 320/400/480 CSS 像素宽度及低高度场景制作验证样张，这些是设计测试点，不是已承诺的产品支持边界。最终支持宽度待评审确定。

## 四、对话信息规范

### 4.1 消息角色

| 类型 | 样式与内容 | 禁止事项 |
|---|---|---|
| 用户发言 | 轻背景、可辨识的用户角色；保留原始表达 | 按钮自动生成长指令并冒充用户发言 |
| Agent 结论 | 以正文排版为主；先结论，再依据与限制 | 每段回复包装为重边框卡片，重复整套需求与方案 |
| 过程入口 | 低强调折叠行，如“分析过程 · 检视与复核” | 展示内部推理、原始工具参数流或完整 DOM |
| 操作事件 | 简短只读记录，如“已确认当前范围” | 保留过期的可点击确认按钮 |
| 制品摘要 | 文件式入口：名称、版本、变化摘要、状态 | 在聊天里直接铺满代码或自动运行 |
| 失败反馈 | 直接可见的原因、影响与下一步 | 仅靠 toast 或藏进折叠过程 |

需求摘要默认收起，以“当前需求”入口查看目标、保留约束与待澄清项。只有新变化影响决策时才突出相关条目，不重新铺满整份摘要。

### 4.2 结论结构

建议回复按以下顺序组织，缺项时省略，不强制固定模板：

1. 发现：与诉求相关的观察，引用页面实际目标编号。
2. 建议：拟处理范围及隐藏/弱化方式。
3. 不确定性：证据不足、未覆盖部分或保留内容冲突。

主要操作统一放在当前决策区；聊天中不再放一套同义按钮。目标行可保留“定位”等局部操作。

### 4.3 过程折叠

- 一轮分析聚合为一个过程入口，内部按活动次序列简短事实，如“读取页面结构”“检视候选关系”“检查重复范围”。
- 运行中默认显示最新活动摘要，可展开查看；完成后未被用户主动展开的过程保持收起。
- 手动展开/收起优先于状态自动更新；流式新内容不重置选择。
- 工具输出只展示必要脱敏证据；复杂结构详情放在证据层，不影响主体可读性。
- 无真实完成比例时用不定进度与活动文字，不显示伪造百分比或预计时间。

## 五、关键决策与输入交互

### 5.1 决策区组件

结构为“动作标题 → 对象摘要 → 关键影响/限制 → 主要操作与次要入口”。同一时间只有一个重点决策；历史决定回到对话只读记录。

| 场景 | 对象摘要 | 主要操作 | 次要操作 | 点击效果 |
|---|---|---|---|---|
| 需页面证据 | 当前绑定页面与读取边界 | 授权读取当前页 | 暂不读取 | 获权后自动分析 |
| 范围待确认 | 建议数量、保留要求、处理方式及不确定性 | 确认范围 | 核对范围、取消 | 只确认范围，不生成 |
| 范围已确认 | 当前范围与隐藏/弱化方案 | 授权生成 | 修改方案、取消 | 自动生成并检查，不运行 |
| 页面已变化 | 受影响范围与失效原因 | 重新核对页面 | 查看旧结果 | 按需要重新授权，复核后再决定 |
| 结果待核实 | 当前版本与未收到的回执 | 核实运行结果 | 查看记录 | 查询既有结果，不再次运行 |

运行和保存主要在制品视图完成；对话中仅提供“查看脚本”入口，避免出现两个相互竞争的操作中心。

### 5.2 范围核对视图

```text
返回对话                      核对范围
当前需求摘要 · 保留要求
覆盖摘要：已检查范围 / 未覆盖范围

☑ 候选 7 · 页面右侧区域          定位
  可见特征与建议依据
  不确定性（若有）               查看证据
☑ 候选 12 · 页面底部区域         定位
  可见特征与建议依据

手动补选（已有能力）

已选择的范围摘要
[确认范围]                    取消修改
```

- 本视图与决策摘要读取同一目标集合，不维护第二份勾选。
- 目标编号贯穿聊天、列表和页面标注；显示顺序改变不能重新分配编号。
- 定位只标出对应节点，不改变选择、确认或授权；已有标注可关闭。
- 用户取消的目标记录为本任务排除要求。手动补选进入同一集合，并触发相关范围复核。
- 存在未解决的嵌套、范围冲突或失效目标时，明确指向相关行，确认不可用并显示原因。
- 空选择时显示“尚未选择处理范围”，确认不可用；不推荐“全选结构节点”作为解决办法。
- 处理方式在范围摘要旁以隐藏/弱化的明确选择呈现。修改方式影响当前方案授权，不暗中改变范围。
- 返回未确认时保留临时修改并显示“范围有修改，待确认”；若选择放弃修改，则恢复进入前仍有效的选择。
- 确认成功后返回对话，在同一决策区呈现生成授权；不再要求点击额外分析或继续按钮。

### 5.3 输入与停止

- 空闲时 Enter 发送、Shift+Enter 换行，发送空白内容不可用；中文输入法组合输入时 Enter 不发送。
- 发送只提交用户消息，不隐含页面授权、生成、运行或保存。
- 本版采用简单策略：活动任务中允许编辑草稿，不提交新一轮消息；提示“可先补充输入，当前任务结束后发送”。不引入双队列。
- 活动中主要动作位为“停止”，名称及图标均可识别；停止请求提交后显示“正在停止”，避免重复点击。
- 停止后显示真实结束状态，保留消息和候选。已经执行的页面变化不会因停止自动恢复。
- Esc 优先关闭当前菜单或弹层；没有这些上下文且不处于组合输入时，才用于停止可停止的 Agent 工作。
- 页面脚本运行已提交但不可取消时，明确显示“正在等待运行结果”，不能将 Esc 或停止宣称为撤销脚本。

## 六、脚本制品视图

### 6.1 布局

```text
返回对话                 脚本名称 · 版本
候选 / 已修改 / 已保存      版本信息

说明与本次变更摘要
适用页面 · 权限 · 运行时机  查看详情

代码                 复制完整脚本  编辑
完整 UserScript 元数据头
功能正文

当前版本运行与效果记录
目标结果 / 保留检查 / 覆盖限制

当前操作说明
[授权试运行当前版本]          更多操作
```

代码默认只读，编辑为显式模式。正文和元数据共同构成完整制品；不可仅复制正文。历史版本只读查看不获得当前运行许可。

### 6.2 状态与操作优先级

| 制品状态 | 突出操作 | 其他操作及限制 |
|---|---|---|
| 正在生成 | 无运行操作；显示进度和停止 | 不将局部代码当作可安装候选 |
| 检查失败/未就绪 | 查看问题 | 阻止运行和兼容导出，不伪装完整可用脚本 |
| 候选已检查，尚未试运行 | 授权试运行当前版本 | 复制、编辑可达；保存是否可用服从现有门禁 |
| 已编辑、待检查 | 检查当前修改 | 编辑不自动运行；旧版本通过标记不跟随新内容 |
| 正在运行/检查 | 显示进展，阻止重复提交 | 复制可用时保持可用，编辑需避免改变执行中的版本 |
| 局部计划检查通过 | 保存当前版本（满足既有门禁时） | 继续显示覆盖范围，不写“全部目标完成” |
| 发现问题 | 查看问题与修复建议 | 请求生成修复需另行授权；不能自动运行新版本 |
| 无法完整判断 | 查看证据与未检查项 | 保存按既有门禁呈现原因，不自行新增放行或禁用规则 |
| 已保存 | 导出保存版 | 查看、复制可达；再次运行仍独立授权 |
| 旧版本/页面失效 | 查看历史记录或重新核对 | 不把旧结果当作当前有效确认 |

“更多操作”不隐藏当前任务需要的主要决策；导出在已保存状态直接可达，次要动作均有文字标签。

### 6.3 编辑、授权与版本表达

- 进入编辑前明确当前版本，编辑后标记“有未保存修改”。放弃修改需明确选择，离开不丢失草稿。
- 匹配范围、权限、运行时机与代码关联；修改后显示具体变化及需重核事项，不能仅靠改头注释提权。
- 运行授权摘要就地展示版本、适用页面、处理范围、权限和时机；以“授权试运行当前版本”完成一次授权，不再增加第二个同义确认弹窗。
- 保存按钮指向明确版本，成功后显示保存回执；保存不隐含启用新行为或再运行。
- 导出存在未保存修改时明确“导出的是保存版”；不能暗中将草稿替换到导出文件。
- 查看详情、复制代码不引发授权；复制成功使用轻量反馈，失败则给出可重试的明确反馈。
- 旧脚本缺匹配范围或权限依据时显示“待复核”，可读原正文，但不标为已兼容或允许跳过门禁。

## 七、运行、效果与修复反馈

### 7.1 三层结果分别展示

| 层次 | 典型文字 | 不能替代的结论 |
|---|---|---|
| 执行回执 | 当前版本已执行 / 执行失败 / 结果待核实 | 不等于效果通过 |
| 局部效果 | 确认范围检查通过 / 发现问题 / 无法完整检查 | 不等于整个页面目标完成 |
| 覆盖与保留 | 已检查的目标和保留区域、未覆盖部分 | 未检查不等于无误伤或无遗漏 |

报告默认给出摘要，目标逐项结果和保留异常按需展开；误伤、失效及无法判断的原因保持直接可见。报告始终标明对应版本与页面。

### 7.2 修复路径

发现问题 → 显示原因与证据 → 提出修复方案 → 范围变化则重新确认 → 授权生成修复版本 → 查看候选 → 独立授权试运行。

用户无需操作补证工具；内部有限循环以任务状态体现。相同失败反复发生、无新证据或预算耗尽时，停止并总结已完成与缺口，不显示无限转圈。旧脚本影响仍存在时直接说明当前页面状态，不提供没有实现依据的“恢复原状”按钮。

## 八、设置 UI 与配置体验

### 8.1 概览

```text
返回                      设置

模型与服务
当前使用方式 · 当前模型
状态图标 + 可用性说明             管理 →

设备与连接
本地服务与配对状态                查看 →

外部入口
已有集成摘要                      管理 →
```

每组使用轻边框和明确标题，状态通过图标、文字与颜色共同表达。已支持的使用方式作为服务选择入口；不展示尚未支持的服务来制造能力错觉。

### 8.2 服务选择与详情

- 先选已有服务或支持的使用方式，再进入配置详情；选项多时提供名称搜索，搜索无结果显示空状态。
- 详情顺序：服务身份与说明 → 模型 → 必要凭据 → 连接状态/测试 → 高级参数。
- 本地方式不展示无关 API 表单；API 方式不要求无关本地配对配置。设备状态与模型状态分别展示，不能用一个“已连接”代替两者。
- 高级参数默认收起，概览不铺端点、协议和超时；必要术语保留准确名称并用短说明解释。
- 凭据默认遮蔽；显式显示、替换和清除，不在状态文案或错误详情中回显原值。
- 字段标签常驻，placeholder 只作示例；错误放在字段附近，保留输入并明确修正方式。
- 保存和测试为不同动作。测试运行时写明“测试当前填写内容”；未保存的测试通过不得显示为已启用配置。
- 修改配置后旧测试标记为过期。测试结束时只更新对应配置，不覆盖后续修改。
- 保存为主要操作，测试为次要操作；保存中显示真实状态并防止重复提交，保存失败保留表单。
- 离开未保存详情时提供“继续编辑”“放弃修改”；不要求用户重新填写已有有效配置。
- 活动任务不被配置更换静默切换模型，按 PRD 保持原绑定或明确中断。

### 8.3 状态与诊断文案

| 状态 | 文案方向 | 可提供动作 |
|---|---|---|
| 未配置 | 尚未选择可用服务 | 配置服务 |
| 正在测试 | 正在检查当前配置 | 防止重复测试 |
| 测试通过但未保存 | 当前填写内容测试通过，尚未保存 | 保存 |
| 已配置且已验证 | 当前服务可用，展示已验证对象 | 管理 |
| 未验证/结果过期 | 配置已保存，尚需测试或测试已过期 | 测试 |
| 连接不可达 | 无法连接服务，说明受影响能力 | 查看连接配置/诊断 |
| 凭据无效 | 当前服务的身份验证失败 | 更新凭据 |
| 模型/能力不可用 | 连接存在，但选定模型或所需能力不可用 | 修改模型/查看详情 |

状态来自真实测试或连接证据，不能仅凭保存成功标记为可用。具体协议选项、默认服务和超时边界按 PRD 待确认项处理。

## 九、全局状态、恢复与反馈规范

| 状态/事件 | 主反馈位置 | 交互规则 |
|---|---|---|
| 普通聊天 | 对话 | 不出现页面流程或授权倒计时 |
| 分析/生成中 | 输入附近任务状态 + 过程入口 | 不定进度，可编辑草稿和停止 |
| 等待决定 | 当前决策区 | 说明对象与后果，停止加载动画 |
| 页面变化 | 可见状态提示 + 对应目标/制品标记 | 阻止旧授权运行，不自动切换新页绑定 |
| 已停止 | 状态摘要 | 保留成果，无自动回滚承诺 |
| 断连/结果未知 | 持续可见提示 | 先核实实际状态，不提供直接重复执行的快捷按钮 |
| 失败 | 相关区域内错误 | 原因、影响、恢复入口直接可见 |
| 复制成功 | 轻量短反馈 | 不打断阅读、不移动焦点 |
| 保存成功 | 制品状态及回执 | 持久可见版本信息，轻反馈只作补充 |
| 重开/返回 | 恢复来源视图及阅读 | 授权和身份另行验证，迟到回执不能覆盖当前状态 |

错误文案采用“发生了什么 → 哪部分受影响 → 下一步”。诊断技术详情可展开，不把原始错误码当作唯一提示。未经真实进展确认不显示“已完成”，未收到回执不显示“失败后可立即重试运行”。

## 十、视觉系统建议

### 10.1 视觉方向

采用中性背景、清楚文字、轻边框和有限强调色。沿用 Luban 品牌主色并形成统一变量，不直接混用 pi-web 的配色和现有零散颜色。当前页身份、主体结论和主要操作分别有清楚层级。

| 视觉角色 | 用途 |
|---|---|
| 页面背景/面板背景 | 区分主内容与输入、设置容器 |
| 正文/辅助文字 | 结论与次要说明；辅助文字仍需可读 |
| 边框/分隔线 | 轻量分组，不为每条消息加重框 |
| 强调色及交互态 | 当前主操作、链接、选中与焦点 |
| 成功/注意/错误 | 与文字及图标一起表达状态，不替代业务结果描述 |
| 代码文字/背景 | 制品阅读，与聊天正文区分 |

### 10.2 初版设计参数

以下是本设计稿提出的起点，需在原型中验证；不是把 PRD 的待确认参数当作已确认值。

| 项目 | 建议起点 | 验证重点 |
|---|---|---|
| 正文 | 14px，行高约 1.6 | 中文连续阅读、窄侧栏与缩放 |
| 辅助文字 | 12–13px | 关键状态不得靠缩小文字隐藏 |
| 页面标题 | 16px，中等字重 | 标题不压过主要内容 |
| 间距 | 4px 基础步长，常用 8/12/16px | 同类组件一致，长内容不拥挤 |
| 圆角 | 控件约 6px、容器约 8px | 不制造过多嵌套胶囊与装饰 |
| 文字按钮高度 | 约 36px | 可读标签、键盘聚焦与窄屏换行 |
| 图标按钮热区 | 约 32px 起 | 图标之外有足够可点击空间和可读名称 |
| 内容边距 | 约 12–16px | 窄宽度仍有可用文字行长 |

hover、focus、pressed、disabled、loading 状态都需定义；禁用操作若原因不明显，应有就近说明，不能只变灰。关键内容需检查对比度、200% 缩放及现有主题；减少动效偏好下移除非必要动画。本版不新增主题选择系统。

## 十一、可访问性与键盘规则

- Tab 顺序跟随视觉阅读顺序；返回、当前决策、输入和主要操作可达。
- 视图切换后焦点放到新视图标题或首个合理控件，返回后恢复触发入口；焦点不落到已消失的按钮。
- 仅真正的模态层限制焦点范围，关闭后回到触发点；侧栏替换视图不误作嵌套模态。
- 折叠区暴露展开状态，按钮支持 Enter/空格；图标按钮有可读名称，目标勾选与目标摘要关联。
- 若采用选择组，提供正确的选择语义与键盘移动；不为普通链接伪造 tab 角色。
- 关键错误可被辅助技术获知；运行状态按阶段播报，不逐字播报模型流式内容或高频工具日志。
- 默认焦点样式清楚；状态同时包含文字，目标定位不能只依赖不同标注颜色。
- Esc、Enter 均尊重中文输入法；关闭菜单优先于停止任务，停止脚本与停止 Agent 的能力差异可见。

## 十二、代表性体验路径

### 路径 A：仅分析，不生成

输入需求 → 若需真实页面则授权读取 → 自动检视与复核 → 显示结论和范围建议 → 用户核对或停留。未授权生成时没有脚本候选，更不会运行。

### 路径 B：生成、试运行与保存

确认范围 → 同一决策区呈现方案与“授权生成” → 自动生成并检查 → 对话显示制品入口 → 打开完整脚本 → 授权试运行该版本 → 查看执行、局部效果、保留与覆盖结果 → 满足门禁时保存 → 可导出保存版。

### 路径 C：排除误选与修复

核对范围时取消目标 → 排除进入任务约束 → 自动复核相关建议 → 用户重新确认。若已运行后发现问题，展示证据与修复方案；范围扩大重新确认，生成和运行新版本分别授权。

### 路径 D：阅读中断与恢复

阅读旧消息 → 新结果到达，仅显示“查看最新” → 打开制品 → 返回原阅读位置且保留草稿。页面刷新或切换时同时显示需重核提示，恢复界面不会恢复失效授权。

### 路径 E：服务配置失败

设置概览显示不可用对象 → 进入相关详情 → 修改并测试 → 失败原因就近出现且保留输入 → 修正后测试通过 → 明确保存 → 返回原任务。测试通过和保存完成为两个独立反馈。
