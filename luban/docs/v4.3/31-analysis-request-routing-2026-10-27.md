# 分析区域请求遗漏页面绑定的回归修复

日期：2026-10-27。

## 现场与计划

本机最新会话 pageBound=false、模型1次、工具0次，只有 run.started/run.finished。用户的“分析动词＋区域对象”请求没有进入 Extension bind/analyze，而是普通聊天。模型没有尝试页面工具便根据未绑定状态回复未授权。这不是浏览器真实拒绝权限，也不是上一轮总时限问题。

上次区域清单修复仅覆盖“有哪些/列出/找出”，本次漏了“分析/查看/看看/检查”的结构请求。计划扩展通用动词与结构名词组合、处理逗号后的保留要求，加入普通分析与明确禁止读取反例，并验证首条消息绑定。

## 实现

- 区域清单规则统一为 REGION_REQUEST，加入分析、查看、看看、检查等通用请求动词；对象仍为位置、模块、面板、控件、表单等结构词形，没有业务分类词表或网站适配。
- 结构对象后的逗号、空格、标点不再导致整句漏判。
- 已有绑定时，明确检查结构对象的请求优先进入页面分析；“检查效果”等既有结果复核保留原路径。
- 明确不读取、只解释仍优先普通聊天；分析预算、成本、模型、数据库类型等知识对话反例不采集。
- 页面权限仍由原 PageGrants、activeTab、文档/工作区绑定检查决定。本修复不预授权、不跨标签页、不生成或执行模型代码。

## 验收与复核

- 新增11个反例，路由文件40项通过；扩展全量531项通过。类型/构建/lint通过，版本保持0.4.3。
- [真实 Native 验收](evidence/2026-10-27/analysis-routing/native-dom.json)：20项通过。首次“分析一下提示位”不含旧识别/当前页触发词，从工具栏授权后完成 page.bound → search_dom → read_dom_blocks → report_observation，4次模型、只读 answered；输入原文保留、不生成不执行。另回归同文档不重复绑定、独立生成/运行/保存和导航失效。
- Native模型为本机协议夹具，不代表真实广告位语义准确率。没有重试业务页面或改写此前失败聊天。
- 代码复核没有新增广告/站点运行时关键词，相关业务示例仅在测试夹具中。句式路由仍是启发式，本次验证不表示覆盖所有自然语言表达。

## 应用

扩展构建已更新；日常已加载扩展需要重新加载。Bridge代码未改，无需因本次路由修复重启Bridge或重新配对。重新加载后在目标页点击工具栏一次恢复activeTab，再原文发送即可验证实际页面。

复现：设置现有Playwright/Chromium路径和独立输出目录后执行：

```sh
node luban/scripts/verify-v43-native.mjs --entry --dom --batch --inventory-analysis
```
