# 修改模式工具授权清单对齐

## 真实根因

会话 ee00300a-96d8-4933-890d-ff0062cd2f65，用户请求“分析一一下广告区域，帮我隐藏掉”，意图为 modify。在实际检索和读取后，第 3 次模型调用请求 report_observation，宿主以 HARNESS_TOOL_DENIED 拒绝。此结论来自真实检查点的最后一条原生工具调用及宿主失败记录；未导出页面内容或工具参数。见 [根因记录](evidence/2026-10-27/tool-authorization/root-cause.json)。

模型请求的工具确实出现在 Runtime 提供的清单中，但宿主仅允许 identify 调用它。这是产品内部契约不一致，不是用户缺少页面授权，也不是需要用户开放更多能力。宿主拒绝规则应保留。

## 修改

- modify 模式从模型可见工具清单移除 report_observation；后续阶段过滤只能缩小此集合。
- 为修改模式明确说明：复核真实目标后原生提议处理范围；证据不足正常说明缺口，不提交只读报告。
- 只读模式继续使用原有结构化报告、字段修正及引用验证机制。
- 未放宽工具权限、目标确认、生成、运行或保存授权。普通修复版本仍为 0.4.3。

## 验证

- Harness 全量 61 项通过，包含新增“修改模式不得暴露宿主禁止的只读报告工具”测试。
- 浏览器验收增加 modify-tool-list-matches-host 检查，使用实际 Worker 与 Native Messaging、本地确定性模型协议夹具；结果见 [链路记录](evidence/2026-10-27/tool-authorization/native-dom.json)。此记录不证明真实网页语义识别成功。
- Bridge 已重新构建发布包，日常后台仅在无活跃任务时温和重启；实际部署状态见 [部署记录](evidence/2026-10-27/tool-authorization/deployment.json)。本轮只修改后台，无需因本次改动重新加载前端。

原会话的错误消息保留，未自动重新执行用户的网页任务。修复后的真实供应商模型与原页面仍需重新发起任务验证，不能将工具清单对齐视为广告完整识别或隐藏完成。
