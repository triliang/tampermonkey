# V4.3 通用自动生成修复与47用例第二轮复验

## 结果

**共享生成推进缺口已修复：C01–C26及A01的27个关联检查点通过本地状态/模型协议验证。112项已更新逐项记录，但真实模型端到端通过数仍为0。**

固定模型只返回用于核对协议的候选，不实现各用例页面效果。因此这不是26个业务任务完成率；候选是真实Worker保存的制品，语义答案是夹具，二者分开标记。全部112项整体仍需真实模型/前置/效果等证据，不能追认为通过。

## 修复内容

1. **任务意愿独立保存。** 人类改造请求携带独立请求ID、真实消息ID、原文及时间；不要求出现“生成脚本”。该状态仅保存意愿，不批准任何执行。仅改造通道记录，问题、只读、解释、否定、取消做排除；具体完整性仍由需求核验与真实范围确认共同约束。
2. **批准绑定当前版本。** 自动批准校验真实消息来源、完整需求、当前请求ID、已确认范围、方案、需求版本和草稿基线。每次修改分析必须先记录需求，模型跳过或仍有缺项时不能提议目标。模型不能通过工具自称已批准。
3. **确认后自动推进。** 侧栏轮询显式advance操作；分析完成且既有范围有效时自动进入通用生成，范围待确认时只等待具体范围。确认按钮与聊天确认均能推进。get仍为只读。
4. **所有改造走通用程序。** 新主链路统一program，包括隐藏和弱化。旧hide/dim编译器仅保留兼容入口，不再按7/19划分产品能力。
5. **失效与重试。** 范围/需求变化撤销旧批准、保留未取消任务意愿；同一确认版本最多自动尝试一次；错误、预算结束、取消、暂停、格式异常不触发轮询重试。迟到结果由epoch拒绝。
6. **保护现有数据。** 只存只读候选，不应用、不运行、不保存，不覆盖手工草稿；运行与保存的reviewOnly门槛维持。Bridge新增automaticProgramDraft能力标记，缺标记时不进行自动批准。
