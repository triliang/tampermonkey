# 对话处理过程折叠展示

日期：2026-10-27。参考用户提供动图的交互，不执行动图中的学习计划内容。

## 计划

- 用户消息靠右，助手最终回复保持正文流。
- 每轮真实活动置于最终回复前，摘要显示实际用时；运行中可展开，完成后收起，点击可再次展开。
- 最终回复和脚本候选卡片保持在折叠区之外，不随过程收起。
- 只使用宿主真实事件与时间，不编造推理文本、步骤或耗时；保留脚本查看、应用、运行、保存的原授权步骤。
- 验证多轮归属、运行/完成/失败/停止、缺少历史时间、窄侧栏与键盘操作。

## 实施与验收

- 新增按运行轮次分组的聊天过程展示，使用 Bridge 保留的真实事件。普通分析、脚本生成、等待确认、证据不足、失败和停止分别展示；取消时宿主虽然推进 epoch，界面仍将停止事件归入原活动轮次。
- 运行中默认展开并按真实开始时间计时，手动收起后不会被每秒刷新重新打开；完成后自动收起。完成时间固定使用宿主终止事件，缺失历史开始时间时仅显示保留活动，不推算耗时。小于一秒显示“不到 1 秒”。
- 每轮过程放到对应回复之前；没有文字回复的脚本生成过程放在下一轮用户消息之前，不混到后续回答下面。普通消息、附件和代码引用仍保留，不重复渲染旧全局活动列表。
- 用户消息靠右、深绿气泡；助手回复保持正文流。脚本候选采用文件卡片，显示只读说明；收起过程不隐藏最终正文或脚本卡片。保留原查看完整脚本、显式应用、独立运行和保存步骤，未执行模型代码来制作预览。
- 使用原生 details/summary 交互和可见焦点，支持 Enter/空格；尊重系统减少动态效果设置。当前新版 Agent 聊天区采用此结构，旧版非 Agent 兼容路径保留原有行为。

## 交付范围

源码和扩展构建已更新，不改变后端调用预算、授权范围、生成/运行/保存流程或业务识别规则。日常 Chrome 尚未自动刷新，重新加载扩展后可使用新界面。历史事件保留受宿主原有容量上限约束，不宣称能还原已被裁剪的完整链路。

复现：构建扩展后，设置项目已有 Playwright/Chromium 路径和独立输出目录，运行：

```sh
node luban/scripts/verify-v43-native.mjs --entry --dom --batch --ui --chat-process
```
