# 检索收敛与自动核验：第一轮优化

## 目标与边界

按 [真实日志审计](43-retrieval-latency-audit-2026-10-27.md)先修复 P0 闭环与部分 P1 数据重复问题，验证短路径。本轮不接入 Chrome MCP/HtmlRAG，不改为自动选择业务目标，不扩大网页权限。具体目标仍由模型根据用户诉求与实际证据提出，用户确认范围；生成、运行、保存分别授权。

## 实施

1. 修改分析中的 propose_targets 自动执行真实 inspect 与集合 review，通过后才调用宿主原有提议逻辑。最多 8 个模型选定的真实引用，独立 inspect 并行，集合 review 随后顺序执行；任一失效或复核不通过都不会建立提议。内部工具照常计入宿主及本地预算，不绕过旧的拒绝规则。
2. 成功提议由固定模板显示候选编号、依据及待确认状态，立即结束模型，不另花一次模型改写最终回复。外层仍作最终实时复核，确认步骤仍重验节点。
3. 修改模式最多两轮发现线索，或已用约 45 秒时结束宽泛检索；后续保留已有引用读取、inspect、review 和合法提议。删除“允许提议却关闭必需复核”的时间阶段死角。
4. 修改分析设 4 次模型调用的软结束点，整体硬上限仍为 8 次/24 次工具/120 秒。不能形成合法范围则保留缺口并给出手动定位，不让外层重复启动同一段分析；不把技术失败改报为范围歧义。
5. search_dom 返回上限按模型上下文预算压到 8 个排名块；其余仍属未覆盖信息，不宣称整页识别。结合原有 readLimit:4 优先实际批读。
6. query_targets 面向模型仅返回本次匹配且新增/变化的候选摘要；重复项用 unchangedRefs 引用。read_page_context 也使用紧凑摘要。完整目标、指纹与全部注册项留在宿主，操作身份检查不减弱。显式 summaryOnly 标记保留摘要限制；覆盖、截断和游标原样保留。

本轮没有实现全量快照缓存、多查询统一召回或全量历史压缩；浏览器到宿主的 query_targets 传输仍可包含累计集合，主要先减少宿主到模型的重复数据。不是声称已完成审计中的所有 P1/P3 工作。

## 回归

- Harness 66 项通过，新增收尾提议自动核验、失效/嵌套拒绝、两轮发现与四次尝试限制，旧 SDK/授权边界保持。
- Bridge 122 项通过，新增候选摘要去重：累计 60 项，匹配 2 项只发 2 项摘要；重复返回只发引用，完整宿主指纹不变、截断和游标不丢失。
- 原“预算耗尽状态必须 stopped”的断言改为 incomplete，保留已读结果及手动定位建议；原 Worker 至少 5 次模型回复断言改为 4 次，因为合格提议不再需要额外最终模型调用。

## 浏览器前后对照

使用同一包含 60 个额外嵌套模块的通用测试页面，真实 Chrome + Native Messaging + 实际 Worker，本地确定性模型协议夹具。先保存旧发布包基线，再测试新包中“实际读取 → 直接提议 → 宿主核验/复核”的路径。见 evidence/2026-10-27/retrieval-short-path 下 baseline、optimized 与 comparison.json。

这证明可用短路径、真实节点约束、授权流程及非目标区域保留，不证明真实供应商模型一定选择同样路径，也不证明广告识别准确率提升。原真实业务页面本轮没有自动重跑。

## 后续验证

更新后台后复测原需求，优先检查首次合法提议时间、模型调用数、是否重复查询相同引用、失效引用拒绝与覆盖缺口。单次模型响应仍可能很慢，本轮不承诺任何页面固定耗时；下一轮再依据真实结果决定是否实施文档修订缓存、多查询召回、历史摘要或模型/网络分段计时。

版本保持 0.4.3。本轮变更位于后台和共享模板，不需为本轮专门重新加载扩展；页面授权失效时仍须重新打开侧栏授权。

## 最终记录

同页受控路径：修改模型调用 5 → 2，只读 2 → 2；两组各 25 项浏览器检查通过。见 [对照结果](evidence/2026-10-27/retrieval-short-path/comparison.json)。追加最终实时复核失败测试，必须撤回“待确认”提议文案并转为不可确认/手动定位，避免历史提议误导。此反例已通过单测。

发布包已重建，日常后台仅在任务空闲时温和重启；见 [部署记录](evidence/2026-10-27/retrieval-short-path/deployment.json)。
