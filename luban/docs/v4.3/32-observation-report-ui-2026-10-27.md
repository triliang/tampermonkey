# 只读报告格式与后续步骤

日期：2026-10-27。

## 现场与计划

用户看到未执行的 report_observation XML 文本，包含不符合工具定义的字段。只读检查最新会话：identify、incomplete、模型7次、工具10次，实际成功读回1条证据，observationReport为空；最终回复确有工具标记。输出中的多条声明不能当成全部核实过的结论。

计划：内部工具格式不直接显示给用户、不解析成可执行调用；新结果服务端规范化，旧历史前端兼容。明确显示已保留的读回线索、有效报告、缺口和下一步。继续取证必须由用户点击，不自动循环；说明范围不覆盖未发送草稿。

## 实现与验证

### 实现

- 仅把真实工具返回成功后的 observationReport 当作有效报告；没有报告的普通文本不得升级为 answered。
- 新增共享输出规范化：检测最终回复中的未执行工具XML，用正常Markdown说明报告未完成，不解析其中的参数、不补造工具调用、不执行任何动作。Worker在分析结束前规范化，宿主标记tool_markup并保持incomplete；旧历史由前端兼容显示，不改写原聊天存储。正常Markdown与代码示例保留，用户消息只作为数据展示。
- 新增“本轮识别进展”：显示当前保留的实际读回线索数量、报告状态、已提交判断、歧义/缺口与下一步。线索名称直接作为文本，不显示内部引用ID；“已读取”不等于符合需求的目标，保留最多8条事实的既有限制。
- incomplete新增“继续核实缺口”；只有用户点击才发送保持原需求与约束的续查消息，不自动无限循环、不生成或运行。needs_clarification优先“说明识别范围”，聚焦输入框，已有未发送输入不覆盖。
- 运行中与后续普通聊天不复用旧的识别结果卡片。目标确认、生成、试运行、保存的权限和独立步骤保持。
- 针对实际会话只读核对：唯一事实为文字“广告”的关闭控件，未读回其父容器；不能据此确认关联广告主体或其它推荐模块。没有把网站名称、class、任务分类词写入运行时。

### 验收

- 扩展全量534项、Harness50项、Bridge114项通过；类型/构建/lint/Bridge打包通过，版本0.4.3。初轮并发2时一项既有大页面清理钩子超时，未放宽断言或超时值；最终单进程全量534项通过，初轮日志另保留。
- [真实Native格式与续查验收](evidence/2026-10-27/report-ui/native-report-markup.json)14项通过：本地模型故意把status=answered的未执行XML写入最终回复；界面不显示原始协议、宿主无report工具执行事件、结果仍incomplete且明确显示已读2条合成线索/无有效报告。点击继续后真实report_observation被执行并answered，无确认/方案/制品。
- “说明识别范围”不覆盖未发送输入；续查也保留未发送输入。隔离390px截图经手动查看：[未完成与下一步](evidence/2026-10-27/report-ui/report-incomplete-next-step.png)、[续查结果](evidence/2026-10-27/report-ui/report-continued.png)。
- Native验证使用真实Chrome、Content/Gateway/Bridge/Worker和协议模型，不证明原业务页已完成广告位识别。没有自动重试业务页面，未上传原始网页/聊天内容。

### 应用与限制

已更新扩展构建和本机Bridge包，在确认无活跃任务、待发送消息与有效租约后温和重启空闲Bridge，加载宿主状态保护，保留配对/聊天/草稿。见[应用记录](evidence/2026-10-27/report-ui/daily-bridge-update.json)。日常扩展需重新加载后使用新界面。

这是异常输出的保守降级与可见后续操作，不表示模型一定能完成全部语义判断。原始XML里的其它声称没有被当作有效已核实发现恢复；需要实际取证和合法报告才能形成新结论。

复现：构建扩展/Harness并打包Bridge，配置既有Playwright/Chromium路径和独立输出目录后运行：

```sh
node luban/scripts/verify-v43-native.mjs --entry --dom --batch --report-markup
```
