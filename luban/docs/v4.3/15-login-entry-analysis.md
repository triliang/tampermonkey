## 原因与证据边界

1. 初始回复属于会话未绑定，不能用来判断元素采集准确率。浏览器访问权限、会话页面绑定是两个状态，当前 UI 和模型提示未充分说明其区别。
2. 绑定后，入口已经进入产品自身的候选清单，因此本次不是图标缺失或采集遗漏。故障发生在后续分析、关系检视与范围复核阶段。
3. 源码中 `createEvidenceWorkflow` 仅在存在选中目标且复核无异议时成功结束；只读描述没有独立的成功出口。`worker.ts` 的 `analysisOnly` 使用此流程。这与“只识别、不修改”的本次任务存在流程契约不匹配。
4. Bridge 的 `HARNESS_MODEL_BUDGET` 同时用于达到 8 次模型调用或超过 120 秒。UI 的“调用预算”不能单独证明一定用了 8 次调用。本次没有读取完整调用参数或服务端 trace，不能断言每次复核失败的具体诊断，也不能将全部失败归因于模型。

## 后续修复与复验标准（尚未实施）

- 区分只读观察和修改范围分析：只读任务允许以有证据的描述完成，不要求进入修改目标确认。
- 给授权、页面绑定、证据采集提供明确且一致的状态；模型引用当前真实按钮名称。
- 无进展检测覆盖内层工具循环；相同目标、证据和诊断重复时停止并保留已确认事实。
- 预算错误区分调用次数与时间上限，展示具体证据缺口，避免只提示检查模型配置。
- 复验应覆盖：纯图标、图片 alt、父容器 title/aria-label、重复图标、候选不唯一、iframe/Shadow DOM 覆盖缺口，以及只读任务不触发生成、运行或登录。
- 此案例仅证明当前页的结构采集有效、自动分析失败，不代表上述修复已完成或准确率已通过验收。
