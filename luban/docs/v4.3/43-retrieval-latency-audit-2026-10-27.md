# 最近真实会话检索延迟分析与方案

## 证据与限制

检查真实 domain.sqlite 会话事件及各自 LangGraph 检查点，不运行用户页面脚本。最近两轮：

| 会话 | 分析耗时 | 模型调用 | 完成事件 | 结果 |
|---|---:|---:|---|---|
| e6e2c84f-5791-4151-83f7-4c9622432afc | 120.010 秒 | 7 | 检索 5、上下文 1、批读 1、inspect 1、候选枚举 1 | 总时限；结束文案保留 4 处已读结构，无合法提议 |
| 27314da7-6ecd-47c2-b152-c5f06c7faf9f | 120.015 秒 | 7 | 检索 4、批读 4、单读 1、候选枚举 2、inspect 1 | 总时限；结束文案保留 8 处已读结构，无合法提议 |

两轮随后均进行过手动绑定，当前 facts 已重置，不能用当前 facts=0 推断原分析没有成功读取。

检查点保留的工具消息分别累计 127,222 与 129,935 个 UTF-8 字节（不是 token、单次请求大小或费用）。随着聊天历史重送，旧工具数据可能继续进入后续模型上下文；未取得供应商实际用量，不能据此报告准确 token/费用。

工具返回阶段的检查点时间间隔通常约 0.2–2 秒；若干工具结果到下一次模型结果的间隔约 7–41 秒。这个间隔包含模型服务、网络和框架，不应全部叫纯模型推理耗时。尚缺分段计时和完整 provider usage，因此暂不报告精确百分比。

## 根因

1. 主成本是多轮模型控制取证，而不只是 BM25 计算。最新轮连续换词搜索 5 次；除第一次 readLimit=4，后续多次 readLimit=0，并没有形成高效的“检索 → 核验 → 合法提议”。
2. 上下文重复膨胀。read_page_context 返回已有完整候选；query_targets 返回全部累计注册项而不是本次命中。上一轮 viewport/top 两次候选枚举的消息长度均为 25,703 字符，出现重复返回。最新轮单条枚举结果 29,221 字符。模型反复阅读大块结构、通用文本与相近父子节点。
3. 修改流程收尾存在闭环缺口。剩余时间 <=60 秒时允许提出目标，却关闭 inspect/review；目标提议恰好要求 review 通过。上一轮约 119 秒时模型请求 propose_targets，被 SELECTION_REVIEW_REQUIRED 拒绝。这不是把最后一句文案改好就能解决的。
4. 有失败但恢复不收敛：TARGET_STALE、INVALID_TARGETS、HARNESS_TOOL_PHASE_CLOSED 之后仍耗费模型回合。最新轮读取 stale 引用，上一轮也尝试未发出的观察引用。
5. 每次 search_dom 通过页面 observe 重新执行有界采集，缺少按文档/结构修订共享的检索视图。采样 800 节点、最多 240 块的限制意味着宽泛整页需求仍有覆盖缺口，增加关键词不能解决截断。
6. 组合读取只节省部分调用：真实日志证明已生效（search_dom 后紧随内部 read_dom_blocks），但模型仍能多次回到广搜，缺少状态与新增信息量驱动的收敛控制。此前合成页面 3→2、6→5 的结果只能说明局部往返减少，不能代表复杂真实网页总耗时提升。

## Chrome MCP 的实际状态

最近会话实际工具是鲁班自己的 search_dom/read_dom_blocks/query_targets 等，未经过 Chrome DevTools MCP。此前只是借鉴其快照与引用思路，没有安装或接入为鲁班页面后端；不能评价成“Chrome MCP 已试过也没效果”。Chrome MCP 或 HtmlRAG 都尚未成为本轮执行路径。换访问后端本身也不会修复本地的重复上下文、收尾工具闭环和模型反复搜索。

## 方案（按顺序实施，非本轮已经完成）

### P0：修复修改流程闭环

- 将“只核实”和“最终交付”分开。关闭广搜后仍允许对已发出、被选中的引用做批量核实与范围复核；不要允许 propose_targets 却阻断其前置条件。
- 模型给出待提议引用后，由宿主批量调用真实节点核验/inspect/review，再将结果反馈。所有权限与预算照常计数；失败项不升级成目标。
- 复核通过则立即存待用户确认提议，不额外调用模型美化结尾；真实歧义只集中澄清一次。无进展则给出缺口和手动定位，不重复开一轮相同分析。

### P1：一次取证视图，多查询、增量返回

- 每个已授权文档建立有界结构视图，带文档与证据修订号、区域、覆盖游标和真实引用。一次执行多组通用查询，合并去重后返回摘要；不让模型逐个换关键词。
- query_targets 默认仅返回本次命中、新增/变化记录及游标，不回传所有累计候选；需要目录时用独立的紧凑摘要。
- 修改、导航、节点身份或相关结构变化时失效/局部刷新。快照用于召回，操作前仍必须实时核验，不能用缓存绕过安全检查。
- 模型上下文改为“目标、保留要求、证据摘要、未解缺口、当前状态”，旧的大段工具响应不逐轮重复发送；原始证据留在审计存储。

### P2：短路径调度与早期降级

目标链路：结构视图与多查询 → 模型选待核验引用 → 宿主批量核验/复核 → 模型一次语义判定并提议范围 → 用户确认与已授权生成。一般争取 2–3 次分析调用；只为真实新缺口预留一次补证，不承诺任意页面固定耗时。

重复查询或只返回相同引用不能算新进展；工具错误分为失效、引用错误、预算关闭等分别处理。约 30–45 秒仍没有足够的可操作证据时主动给出已读结果与手动点选入口，让用户选择继续，不必每次无反馈地等满 120 秒。具体阈值需真实模型延迟数据验证。

### P3：测量后再决定 MCP 对照

为模型、页面采集、排序、传输、节点核验分别记录起止耗时、返回字节/引用数、去重命中、新证据数、失败原因、provider token usage（若提供），并校验不得记录页面敏感内容或密钥。阶段信息持续展示。

先完成 P0/P1，再对同一页面、同一模型、同一需求做现有后端与可选 Chrome MCP 后端 A/B。比较首个有效目标时间、模型调用数、字节数、核验成功率、误选/覆盖缺口。单纯加长时限、换 MCP 或换 HtmlRAG 不作为当前主方案。

## 验收标准

必须加入复杂、多区域、动态更新、有相似父子容器的通用页面，包含 stale 引用与部分不可访问情况。检查合法提议成功率、保持未授权区域、实时身份校验和人工确认，不能只测最终文案或简单单容器夹具。既有真实会话只作脱敏复盘，不引入站点专属运行规则。
