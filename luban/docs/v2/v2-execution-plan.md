## 1. 执行原则

1. 按阶段依赖推进。退出标准未达标先修复；用户明确授权的延期单独记录，不把未验收项目改成通过。
2. 开始前检查工作区变更，不覆盖用户未提交修改。建立现有测试与构建基线，明确基线提交/工作区快照。
3. 只把代码、自动检查、真实浏览器行为和证据记录全部满足的项目标完成。
4. Demo 可用于交互回归参考；其中关键词生成、localStorage、模拟 CSS 和异常开关不进生产。
5. Chrome 探针发现 API/世界/生命周期假设不成立，先更新技术方案及相关验收，不静默减少需求。
6. 不估造工期、责任人或实际通过结果。本计划是可执行拆分，不是已完成报告。

## 3. 通用检查与证据格式

### 工程检查

在 `luban/` 运行：

```sh
npm test
npm run typecheck
npm run lint
npm run build
```

P0 先记录全部现有失败；后续每阶段跑适用检查，并在退出前完整跑四项。无新增失败且相关基线问题已修复才通过。仅文档修订不需重复整套测试；实现变化按上述执行。

### 浏览器记录

每条验证至少记录：编号、测试代码版本/工作区快照、Chrome 版本、扩展构建类型、允许用户脚本开关、站点权限、初始数据、操作步骤、预期、实际、通过/失败、日志或截图。涉及提交/恢复要记录 current/previous/registeredVersionId/opId。

测试至少包括最低支持 Chrome 138 与一版当前稳定版；无法取得最低版本环境时该项标未完成，不声称兼容验证通过。

### 测试夹具

使用本地可控 HTTP 页面覆盖 DOM、动态内容、同步/异步错误与多文档导航。另备至少两个不同准确主机名，用于裸域/子域及不匹配测试。真实站点单独验证，不能用同一测试页面的十个 URL 充当十站。

新增测试依赖（例如 fake-indexeddb、AST parser）先确认与仓库构建兼容并锁定版本。Mock 只验证可控故障与状态，不代替真实 Chrome 验收。

### 验收步骤与通过标准

1. 用户明确授权某站，保存探针脚本后，**不点扩展图标**新开该站，脚本执行且收到文档绑定回执。
2. 关闭“允许用户脚本”：真实调用失败并呈现可行动提示；重新开启后重新调用恢复，不能仅根据 API 对象存在判断可用。
3. 故意不装桥或阻断 SW 回执：启动壳到期退出，用户正文没有执行；桥恢复后新开页可执行。
4. 先写 GM 值，再新开页面读取新值；定时回调写入也在刷新后存在；null 值与 delete 行为不同。
5. 注册 candidate 而 DB 仍是 A：新开页面不能执行 candidate。重启 SW 后回到 A，或明确不可用，不能静默跑候选。
6. IDB transaction abort 保留原值；确定容量上限的错误路径；记录 GM_info 兼容行为与导出限制。

**退出：** 六项均有真实证据；探针结果已反映到技术方案。任何主链路探针不通过，不进入 P1。探针代码只保留在测试/开发入口，生产不能出现调试权限和异常开关。

## 5. P1：数据模型、迁移与恢复基础

> 实施记录：[P1 数据与迁移验证](./verification/v2-migration-record.md)。180 项测试、typecheck/lint/build 与真实 Chrome 网页 origin 的 8 项仓储检查通过；扩展内完整升级集成仍在最终验收范围。

**目标：** 所有后续功能都依赖同一份可事务提交的数据。

### 任务

| ID | 工作 | 主要改动 |
|---|---|---|
| P1-1 | IDB schema 与事务封装 | scripts/workspaces/conversations/gm/operations/receipts/runtimeStatus/meta |
| P1-2 | V1 迁移、幂等与备份保留 | 原 id 保留；enabled 不转 autoRun |
| P1-3 | CAS、脚本操作队列、运行时 schema 校验 | 拒绝旧 revision 与非法消息来源 |
| P1-4 | 草稿、输入防抖落盘、flush、容量反馈 | 新建草稿可恢复，单条/总容量检查 |
| P1-5 | 启动 barrier、pending 日志与迁移失败状态 | 不双写旧存储，不自动续发模型 |

### 验收步骤与通过标准

- **迁移：** 构造两条旧脚本、一条 enabled=true、独立 GM 数据和已有模型设置。升级后代码/id/GM 保留，自动运行全部关闭，previous/draft/对话为空，Key 和设置未变化。
- **中断：** 在迁移一条后终止 SW，重启不重复创建；成功标志写入前后分别测试，业务来源始终明确。
- **事务：** 在 current/previous 提交前注入 abort，两个版本及 revision 均保持原值；无半份索引或孤立当前版本。
- **并发：** 两个工作区基于 revision=1 写入，第一份成功后第二份返回冲突，保留第二份草稿，不覆盖第一份。
- **容量：** 单版与总容量超过已确定限制，返回明确错误；原 current、previous 和已落盘草稿不被自动清理。
- **恢复：** 新建/已有工作区写入后重开可恢复；未结束生成标 interrupted，不自动请求模型。

**退出：** 仓储集成测试通过，迁移及并发六类证据记入 `verification/v2-migration-record.md`；四项检查通过。不得继续让旧 SAVE_SCRIPT 任意覆盖新记录。

**目标：** 自动运行关闭时先完成可靠的内容生命周期。

### 任务

| ID | 工作 | PRD |
|---|---|---|
| P3-1 | SW 读取草稿、扫描与页面定向试运行 | F4 |
| P3-2 | 生成 trial receipt，hash/document/有效期校验 | F3/F4 |

| P3-6 | 新建试运行 GM namespace 与首次保存迁移 | F4/Q1 |

### 验收步骤与通过标准

- 新草稿未确认不执行、未试运行不能保存。直接构造消息绕过 UI 也被 SW 拒绝。
- 试运行完成后改 code/grants/runAt，原 receipt 无效；页面导航或凭证过期后保存要求重试。仅改名不重复运行。
- 注入机制成功但用户代码抛错、超时或目标未验证，分别展示正确状态。报错/超时不签发凭证，不显示“已隐藏目标”等无证据结论。
- A 首次保存 previous 为空；B 更新成功 previous=A；恢复 A 后 previous=B；再恢复回 B。对话、名称、GM 数据和开关不被恢复。
- 试运行、改名、失败保存均不轮换 previous。IDB 失败、并发冲突和响应丢失三种情况下，无可用版丢失、无重复轮换。
- 有草稿点恢复：取消保留草稿；确认放弃后才能继续恢复。恢复成功提示刷新，不伪称页面即时撤销。
- 同一脚本重复试运行，无重复组件/事件操作；刷新验证保留草稿。
- 新建试运行 GM 值首次保存后可读取；明确试运行副作用不会因取消而回退。

**退出：** AC03–AC07、AC09 在此阶段对应部分通过；`verification/v2-version-record.md` 记录 A/B 版本 id/hash、receipt 与失败结果；四项检查通过。可用结果为手动工具完整闭环，尚不宣称 V2 核心完成。

## 8. P4：自动运行、外部注册一致性与删除

> 实施记录：[P4 自动运行验证](./verification/v2-auto-run-record.md)。准确授权、注册桥与启动门禁、持续 GM、版本协调、停用/删除/重启恢复及状态 UI 已实现；243 项测试和四项工程检查通过。computer use 只验证 HTTP 夹具中的 UI/仓储/协调器；真实扩展八项主流程和九行强制中断证据尚未全部取得，P4 不标全量退出。

**目标：** 从可靠手动工具变为可持续生效的工具，任何中断都不会误跑未提交版本。

### 任务

| ID | 工作 | 主要改动 |
|---|---|---|
| P4-1 | 可选准确 host 权限、UI gesture 与真实状态 | host policy、manifest、权限适配 |
| P4-2 | 每站内容桥、每脚本注册、启动门禁与执行 lease | bridge/runner/register adapter |
| P4-3 | 持续 GM 增量、去重、sender/grant 校验 | GM service 与回执 |
| P4-4 | 更新/恢复日志协议与 source 校验 | version service + operations |
| P4-5 | 启停、tombstone 删除、启动/更新/权限 reconcile | cleanup/recovery |
| P4-6 | 最近错误、不可用状态与修复入口 | runtimeStatus、UI |

### 主流程验收

1. 首次保存默认关闭，用户开启才请求准确 host 权限。拒绝：脚本仍保存，开关关闭且解释原因。
2. 开启后不点图标新开匹配站点运行；其他主机名、裸域/不同子域、不支持协议不运行。manifest 无安装时 `<all_urls>` 权限。
3. 同站两条脚本独立执行、共用一座桥；停用一条不影响另一条。站内无刷新跳转不重复执行，行为记录为范围边界。
4. current=A 更新 B：之后新开页只获准 B；恢复 A：之后新开页只获准 A。草稿 B 未保存不会改变运行 A。
5. GM 同步、Promise、定时回调写入刷新后可读；null 与 delete 区分；多标签不同 key 不丢写，同 key 按最后提交，旧 lease 不再写入。
6. 关闭、删除或撤销权限后新开页面不再执行；已有页面效果可能仍在，文案准确。清理失败可见且可重试。
7. SW 休眠/重启、浏览器重启和扩展更新后按 committed 数据补注册，旧脚本不会误开启，tombstone 不复活。
8. 来自 MAIN 的伪造管理请求、越界 scriptId、错误文档、超量消息被拒绝；不暴露 Key 或通用网络代理。记录 MAIN 对宿主页不保密的边界，不宣称 token 是绝对隔离。

### 故障断点矩阵（每项必测）

| 中断/失败位置 | 恢复后的通过标准 |
|---|---|
| PREPARED 日志之前 | A 与 previous 不变，无候选注册 |
| 日志已写、update 之前 | A 仍为事实来源，重启清理 pending |
| candidate 已注册、DB commit 之前 | candidate 不能通过门禁；重启补回 A 或显示不可用 |
| Chrome update 失败 | A 保留，B 草稿保留，不轮换 previous |
| Chrome 成功、IDB commit 失败 | 不报保存成功；回补 A，回补失败则暂停许可并显示错误 |
| DB commit 成功、UI 未收到响应 | opId 查询返回 B 已提交，重试不再次轮换 |
| 关闭状态写入后 unregister 失败 | 后续启动被拒，清理待重试可见 |
| tombstone 后删除清理失败 | 不再运行、不复活，记录保留供重试 |
| 权限撤销/开关关闭导致 API 抛错 | 显示不可用，保留内容，不自动请求更广权限 |

测试断点由 adapter 故障注入和真实强制停止 SW 组合覆盖；不能仅 mock 成功回调。
