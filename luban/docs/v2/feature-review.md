# 鲁班 v1 功能评审

> 评审日期：2026-10-11
> 对照：[`v1` PRD](../v1/ai-automation-product-requirements.md)、分阶段任务与 Phase 1–7 验证记录，以及当前 `luban/src` 实现。
> 配套：[同类产品调研](./competitive-research.md)、[优化机会](./optimization-opportunities.md)

## 结论

主链路已经接通：在当前页点选元素、说出意图、流式生成脚本、确认后注入运行、保存并再次手动运行。工程骨架（状态机、脱敏、安全扫描、BYOK、Service Worker 恢复）比「能演示」更完整。

它还不是可以对外发布的产品。价值停在「这次帮我改一下」，没有变成「下次打开这个站自己生效」。质量验收（10 个场景、10 个站点、耗时）没有实测基线。首页仍留着开发自检，隐私页是空的。

一句话：鲁班现在是一个可自测的脚本生成器，还不是「说出意图，工具即成」。

## 已交付

对照 PRD 的 P0，下面这些已经在代码里，并且多数有单测或阶段实测。

| 能力 | 现状 |
|------|------|
| 点选元素 | 悬停高亮、点击拦截、Esc 退出 |
| 页面上下文 | URL / 标题 / 目标元素 / DOM 摘要；敏感参数与密码框脱敏；输入框、按钮、深度限流 |
| 选择器 | id、稳定 data 属性、稳定 class、结构兜底，按稳健度排序 |
| 意图 | 自由文本 + 快捷意图（高亮、隐藏、下载、填充、刷新、监控、去广告） |
| 生成 | 小米 MiMo，OpenAI 兼容；Token Plan 与按量付费可切换；流式输出；超时重试；取消 |
| 预览 | 先看自然语言解释，代码默认折叠；风险提示；置信度偏低时提示重生成 |
| 安全 | 执行前必须确认；`eval`、清空存储、死循环等静态拦截；超出 GM 白名单拒绝或打桩 |
| 运行 | 注入页面主世界；`GM_addStyle`、`GM_setValue` / `getValue` / `deleteValue`、`GM_info`、`unsafeWindow` |
| 脚本库 | 本地保存、最近 3 条、设置页列表、当前页再运行、删除 |
| 失败恢复 | 断网时禁用生成、本地再运行仍可用；生成中和预览可在 Service Worker 休眠后恢复 |

Phase 6 的保存、重开、换站、仅本次运行、出错回灌、休眠恢复，已有真人实测通过记录。Phase 7 只通过了断网四项；Key 无效、限流、注入失败、运行报错、Benchmark 和 10 站注入标为暂不验收。

## 和 PRD 的缺口

这些不是实现疏漏的全部，而是用户能直接感知、或会挡住发布的缺口。

| 缺口 | 影响 |
|------|------|
| 隐私与安全页只有一句「将随后续阶段落地」 | 用户看不到「哪些页面信息会发给模型」，和 PRD 的隐私承诺对不上 |
| 空闲页保留「通信链路自检」 | 第一屏像调试工具，不像给普通用户用的入口 |
| 必须先点中一个元素 | 口号是「说出你想干嘛」。去广告、暗色、批量提取图片这类整页任务，被绑在单个元素上 |
| 保存后不会自动运行 | `@match` 持久注入明确放到了 P1。脚本存下来之后，下次还得自己打开鲁班再点一次 |
| 不能改脚本 | 设置页只有运行和删除。生成偏了只能整段重来，开发者无法微调选择器 |
| 只有小米 MiMo | 适配器是通用的，产品上没有放开其它 OpenAI 兼容端点 |
| 跨域 iframe 的降级提示未单独落地 | Phase 7 记录写明：点选 iframe 时没有「上下文不完整」的专门提示 |
| 质量数字是空的 | 一次生成可运行 ≥ 7/10、注入 ≥ 8/10、端到端 P95 ≤ 15 秒，都还没有记录 |

PRD 里的 P1（主动分析此页、编辑器、自动运行、更多 GM API、多模型、导入导出）按计划未做，不记为缺陷。它们决定了 v2 该先补什么，见优化文档。

## 体验判断

**价值闭环是断的。** PRD 把「7 日内再次运行」和「周留存」写成成功指标，但当前产品做不到「回到这个网站就生效」。用户付出的是一次生成，得到的是一条还要记得去点的记录。没有复利，留存指标无法成立。

**第一步比口号重。** 普通用户要先理解「选中一个元素」，再写意图。列表页、整页样式、表单填充，真正的目标往往不是某一个节点。点选是开发者心智，不是 no-code 心智。

**确认运行缺少「这次会改什么」的证据。** 解释文案是对的，但运行成功后主要是成功或失败标题，看不到页面上哪一块变了。不敢点「运行」的人，不会变成会保存脚本的人。

**安全说得比做得满。** 确认、脱敏、黑名单方向正确。Key 只是 base64 混淆，不是加密。静态规则挡不住绕写。隐私页没有把实际上传字段展示出来。对外不能把这套说成「密钥加密、敏感站点可控」。

**发布路径和模型条款冲突。** PRD 附录已经写明：小米 Token Plan 限定编程工具，禁止用在自动化脚本和自定义应用。开发自测可以用；默认引导用户用 Token Plan Key 对外发布，有封 Key 风险。

## 应该保留的判断

这些选择是对的，v2 不要为了「更像聊天插件」推倒。

- 产出物是可复用的用户脚本，不是替用户点一次按钮。
- 模型看到的是脱敏后的结构化页面，不是整页 HTML，也不是截图。
- 先解释、后代码、确认了才运行。
- 不自建后端，Key 留在本机，请求从扩展后台发出。
- Provider 做成可替换适配器，而不是把 MiMo 写死在调用链里。
- 失败可以带着错误回到意图，而不是让用户从头再选一次元素。
