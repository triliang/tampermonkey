# V2 P3 试运行、保存与恢复验证

日期：2026-10-14，Asia/Shanghai。状态：代码实现、工程检查及本地 UI 夹具验证完成；真实扩展权限、GM 与生命周期集成已获用户人工验收确认；逐项故障证据及最终综合验收仍单独保留。

## 实现

- 后台读取工作区草稿，acorn 8.19.0 校验语法，检查危险代码与 GM grant，再向准确 tab/document 注入 MAIN 正文。没有 eval/new Function 或 script 标签降级；new Function 仅出现在运行时单元测试入口。
- 成功且未超时才签发 30 分钟凭证，绑定工作区、code/grants/runAt 的 SHA-256、页面与文档。重新试运行先撤销旧凭证；代码变化、页面导航、过期不能沿用旧结果保存。
- 注入错误、正文错误、执行超时分别反馈；正文错误进入该工作区对话，下一轮生成可看到。不推断视觉效果，仅提示“执行完成，请检查页面”。
- 首次保存 previous 为空；内容更新将 current 移到 previous；恢复交换两版。改名、试运行和失败提交不轮换版本。
- 保存/恢复以 IDB 单事务完成版本、工作区、凭证、GM 迁移和 opId 结果记录。重复同 opId 返回原结果，参数不同则拒绝；并发冲突保留失败方草稿。
- 新建试运行 GM 使用 workspace namespace，首次保存原子迁入 scriptId。null/set 与 delete 区分；报错前已产生的写入仍保留。新工具 scriptId 使用工作区 UUID，保持保存前后执行标记一致。
- 同一工具、正文和文档只执行一次，防重复组件/事件副作用；再次真正执行需刷新网页。恢复明确要求刷新，不承诺即时撤销旧页面变化。
- 有草稿恢复必须再次确认放弃；取消保留草稿。名称单行、1–100 字；改名不要求重新试运行。
- 旧 SAVE_SCRIPT 与前端传入任意代码的 INJECT_SCRIPT 入口已拒绝；旧设置页的直接新建保存入口因此不可用，后续管理页应接入工作区。已有保存版的手动运行接口仍保留。

主要源码：`services/version-service.ts`、`services/trial-runner.ts`、`shared/p3-types.ts`、SW 路由、工作区仓储与侧栏 App。

## Computer use

环境：既有 Chrome 155；`http://localhost:18888/p3-browser.html`。使用正式 App、VersionService 与 IndexedDB 仓储源码，独立 HTTP 数据库；页面身份、模型和试运行 executor 为模拟替身。无真实 Key、无外发模型请求、不操作正式扩展数据。

1. 创建新草稿 A：未试运行时保存按钮禁用。
2. 确认试运行、填写名称“P3 版本工具”、保存：显示“已保存，自动运行关闭”，previous 无恢复入口。
3. 手改为 `console.log("P3-B");`，重新试运行并保存：出现“恢复上一版”。
4. 确认恢复：代码回到初始生成的 A；再次恢复回到 B，均提示刷新网页。
5. 修改为 C 后进入恢复确认并取消：C 草稿仍在；保存按钮因代码修改已失效。
6. 模拟试运行失败：错误出现在界面及当前对话。关闭故障后重新试运行可保存。

截图见 [浏览器结果](./evidence/p3-browser.png)。夹具复现：在 `luban/` 运行 `node tests/p2/build-browser-probe.mjs`，以 HTTP 服务打开 `spike-v2/p3-browser.html`。
