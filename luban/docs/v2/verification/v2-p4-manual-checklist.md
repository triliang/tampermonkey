## 2. 开启并验证自动注册

1. 在工具工作区点击「授权此网站并开启」。
2. 如果出现 Chrome 授权提示，允许访问 localhost。
3. 另外新开一个标签页，输入 `http://localhost:18888/fixture.html`。
4. 在这个新页面上，不点击鲁班图标，也不点击试运行。

**预期：** 新页面自动显示 `P4 A · 自动运行测试`。

如果仍显示 WAITING 且控制台没有错误：在正式鲁班侧栏打开该工具，点击「查看自动运行诊断」，复制诊断 JSON 交给开发排查。若提示 `Only permissions specified in the manifest may be requested.`，先重新加载最新 dist；诊断中的 declaredOptionalHostPermissions 应包含 HTTP/HTTPS 声明，requestedOrigins 应为该准确主机的 HTTP/HTTPS 两项。该入口需要重新加载包含诊断功能的最新 `luban/dist`。先保留失败结果，不把后续刷新成功改成首次通过。

**预期：** 127.0.0.1 页面保持 `WAITING · 未执行用户正文`。localhost 工具不应在另一个主机名上运行。

## 7. 精确故障断点：需要开发调试配合

> 人工验收：2026-10-14，用户确认本部分“符合预期”，记录为本部分整体人工验收通过；未附逐断点日志、截图或中断位置记录，逐项证据仍待归档。

第 4、5 项验证真实停止、重载、重启后，能否恢复已提交版本。它们不等于命中了保存或删除事务中的精确中断位置。

以下断点不能通过普通界面操作稳定命中：

| 精确断点 | 需要验证的结果 | 人工证据状态 |
|---|---|---|
| PREPARED 日志之前失败 | A / previous 不变，没有候选注册 | 本节人工通过，逐项证据未附 |
| 日志已写、Chrome update 之前停止 | A 仍是事实来源，重启清理 pending | 本节人工通过，逐项证据未附 |
| candidate B 已注册、DB 尚未提交时停止 | B 不能通过门禁；重启回补 A 或明确不可用 | 本节人工通过，逐项证据未附 |
| Chrome update 失败 | A 保留，B 草稿保留，不轮换 previous | 本节人工通过，逐项证据未附 |
| Chrome 成功、DB commit 失败，或回补途中再次停止 | 不误报保存成功；回补 A，失败则暂停许可并显示错误 | 本节人工通过，逐项证据未附 |
| DB 已提交、UI 响应丢失 | opId 重试返回已提交 B，不再次轮换 | 本节人工通过，逐项证据未附 |
| 关闭状态写入、unregister 尚未成功 | 新启动被拒，清理可重试 | 本节人工通过，逐项证据未附 |
| tombstone 已写、删除清理尚未完成时停止 | 不再执行，不复活，重启继续清理 | 本节人工通过，逐项证据未附 |
| 撤权或关闭用户脚本导致真实 API 失败 | 内容保留、不可用提示明确、不请求更广权限 | 本节人工通过，逐项证据未附 |

需要专门断点调试或测试构建记录中断位置。不能仅凭随机点击 Stop 就将这些断点标为通过。现有自动化故障注入覆盖相关逻辑，但不替代真实精确断点证据。
