# 优化机会

> 日期：2026-10-11。依据：[功能评审](./feature-review.md)、[同类产品调研](./competitive-research.md)。
> v1 需求与实现记录在 [`../v1/`](../v1/ai-automation-product-requirements.md)。

## 原则

先让「生成一次」变成「这个网站以后自己生效」，并让人敢点运行。不要把侧栏补成 Monica，也不要先做跨站代理。

排序看用户是否会第二次打开，不看功能听起来是否完整。

## 发布前要补齐

这些不增加新能力，但当前状态对外会失真。

1. **补上质量基线。** 按 v1 PRD 的 10 个场景和 10 个站点做完记录：一次能否跑、耗时、有没有被安全扫描拦住。没有这张表，改 Prompt 或换模型无法判断是变好还是变差。
2. **拿掉空闲页的通信自检。** 第一屏只留「开始选择」和最近脚本。自检留在开发构建里。
3. **隐私页写成事实，而不是占位。** 用当前这次采集结果展示将发送的字段：脱敏后的 URL、标题、选中元素、有限的 DOM 摘要。写明不发送密码、Cookie、localStorage。敏感站点清单和采集深度可以后做，说明不能后做。
4. **默认引导按量付费 Key。** Token Plan 仅作为自测选项，并保留 v1 PRD 附录里的条款风险提示。设置页不要把 Token Plan 写成推荐路径。
5. **运行结果说明改了什么。** 成功页用解释文案加上「已作用于当前页」的具体句子（例如标红了价格、隐藏了选中模块），失败页保持现在的错误回灌。用户要能不打开代码就决定是否保存。

## v2 优先做

按顺序做。前两项不成立，后面的编辑器和多模型只是更好用的一次性玩具。

### 1. 同站自动运行

保存时记下主机名匹配规则，下次打开匹配页面自动注入。设置页可以启用、停用。这是 v1 已定义、被明确推迟的 P1，也是留存指标的前提。

不做跨站规则，不做脚本市场，不默认对所有已存脚本开启。第一次保存仍要用户点「以后在这个网站自动运行」。

### 2. 允许不点选

保留点选，作为「就改这一块」的精确入口。另给一条「描述这个页面」：不选元素，把整页摘要和意图送给模型。再给「分析此页」：返回少量可做的事，点一条就生成，而不是每页自动烧 Token。

点选继续承担价格、按钮、某一条评论这类目标清楚的任务。整页入口承担暗色、去广告、批量提取、定时刷新。

### 3. 生成质量闭环

一次生成可运行，是和 Customaise、VibeMonkey 拉开距离的地方。它们很多只交出代码。

- 运行失败时，把错误和当前选择器带回下一次生成（这条链路已有，要在真实站点上验证）。
- 置信度低或选择器只有绝对路径时，默认不鼓励直接运行，先重生成或改意图。
- 用第 1 节的 10 个场景当回归集，改 Prompt 前后各跑一遍。

### 4. 放开 OpenAI 兼容端点

适配器已经是通用的。设置里增加「自定义 Base URL + 模型名」，而不是只做 MiMo 的两个模型。先支持兼容 Chat Completions 的端点即可，不必为每一家写专用 SDK。

这同时降低单供应商条款风险，也对齐脚本猫、ScriptGenie、Nanobrowser 的多模型预期。

### 5. 保存前能改代码

不需要先上完整 CodeMirror。预览里展开代码后允许直接改，改完再运行、再保存。开发者修一个选择器，比整段重生成便宜，也比「只能删除」能留住脚本。

版本历史和 Monaco 放到这条能力被用起来之后。

### 6. 把快捷意图换成当前页能做的事

现在的芯片是抽象动词：高亮、隐藏、下载。用户面对商品页时，需要的是「价格变化时提醒我」「把主图地址复制出来」。

「分析此页」的建议卡片可以替代大部分芯片。芯片保留 3–4 个高频动作即可。

### 7. 导出标准用户脚本

列表里导出 `.user.js`，使用户能放进 Tampermonkey 或脚本猫。导入放在导出之后。

脚本锁在鲁班里，会在「要不要长期使用」这一步输掉。导出是信任，不是把用户送走。

## 明确不做

| 不做 | 原因 |
|------|------|
| 通用聊天、翻译、总结、搜索增强 | 豆包、Kimi、Monica、沉浸式翻译已经占住；会把「造一个工具」讲成「再问一个问题」 |
| 跨站点击、填表、下单代理 | 信任和提示注入成本高；HARPA、Nanobrowser、Claude in Chrome 已是该形态 |
| 录制回放和工作流画布 | Automa 的主场；和「说意图」抢同一条主路径 |
| 脚本市场、账号、云同步 | 没有自动运行和导出之前，市场没有可分发的东西 |
| 完整 GM_*、`@require`、多语言 | 不提升第二次使用；等自动运行和生成质量有数据再加 |

## 怎么判断 v2 做成了

沿用 v1 的漏斗，补三个只在 v2 才有意义的数：

- 保存时选择「以后自动运行」的比例。
- 这些脚本在 7 天内被自动执行、且没有立刻被用户停用的比例。
- 不点选、直接描述页面而完成运行的比例。

若自动运行几乎没人开，或一开就被停，说明生成结果还不可信，应回到质量闭环，而不是继续加模型或编辑器。
