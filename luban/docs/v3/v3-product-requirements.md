# 鲁班 V3 产品需求：连接飞书与本地 Agent

版本：V3 初稿。日期：2026-10-16。状态：待评审，本文不代表已实现或已验证兼容。

配套评审材料：[PRD R1](./v3-prd.md) · [交互 Demo](./demo-v3.html) · [使用与验证说明](./README.md)。

## 1. 背景与定位

鲁班已有围绕当前网页创建、修改、试运行、保存、恢复和自动运行工具的产品基础。V2.1 将操作集中到固定底部输入、聊天流与代码制品浮层。V3 延续这一交互，增加外部消息入口、供本地 Agent 使用的浏览器能力，以及可替代第三方模型的本地 Agent 会话执行方。

**产品目标：用户可以在鲁班或飞书提出任务，选择第三方模型或本地 Agent 处理；Cursor、Codex 等本地 Agent 也可以通过鲁班获取已授权的网页上下文、生成工具并提交浏览器操作。**

本文的“本地 Agent”指运行于用户电脑、由用户安装并授权的 Agent 产品或运行程序；不等同于本地大模型。Agent 仍可能调用远程模型，其数据流向与费用应按实际配置告知。

### 1.1 依据与基线

| 来源 | 本次使用方式 |
|---|---|
| 用户本轮要求 | 飞书打通（机器人或 lark-cli）、向本地 Agent 提供 MCP、会话可使用本地 Agent |
| [V2 产品需求](../v2/v2-product-requirements.md) | 工具身份、草稿与保存版、上一版恢复、准确主机与自动运行规则 |
| [V2.1 当前需求 R2](../v2.1/v2.1-optimization-requirements.md) | 聊天主线、固定输入、制品浮层、发送信息告知与执行确认 |
| [V2.1 R1](../v2.1/v2.1-optimization-requirements-r1.md) | 质量检查、受控修复、有效目标、失败保护 |

沿用现有文档记录的个人项目与仓库 Markdown 方式。本次未查询企业模板、KBP 或外部平台文档；下文是产品要求，具体第三方接入方式和支持版本须在技术验证后冻结。用户认为基本产品能力已满足使用，不等于历史人工验收遗留项自动关闭。

## 2. 核心场景

| 场景 | 用户操作 | 预期结果 |
|---|---|---|
| 从网页发送到飞书 | 在鲁班整理当前页信息，选择目标并发送 | 飞书收到所选内容，鲁班展示可确认的发送结果 |
| 从飞书发起网页任务 | 向已连接的应用机器人发“整理当前网页表格” | 任务进入鲁班，绑定明确页面，处理后回复摘要或待确认提示 |
| Codex / Cursor 使用浏览器 | 在本地 Agent 中要求读取指定页并修改网页工具 | Agent 通过 MCP 获取有限上下文、提交草稿，鲁班展示结果并控制执行 |
| 鲁班调用本地 Agent | 在原会话选择本地 Agent，继续说“标签还在” | Agent 接收当前工具基线，返回修改后的同一工具草稿 |
| 不可用时恢复 | 本地连接中断、飞书失去授权或请求取消 | 原代码和会话保留，用户可以重连、重试或明确切换执行方 |

## 3. 范围与发布优先级

### 3.1 V3 核心范围（P0）

| ID | 能力 | 最小交付 |
|---|---|---|
| F1 | 本地连接管理 | 用户主动连接本机服务，查看状态、断开、撤销授权 |
| F2 | 向外提供 MCP | 本地 Agent 可发现并使用鲁班支持的网页上下文、工具草稿和任务状态能力 |
| F3 | 本地 Agent 会话 | 鲁班可选择一个通过验证的本地 Agent 完成生成及多轮修改 |
| F4 | 飞书主动发送 | 支持至少一种已验证的方式将用户选定内容发送到指定飞书目标 |
| F5 | 飞书机器人任务入口 | 支持一个应用机器人的收取任务、状态反馈和最终回复闭环 |
| F6 | 统一任务与授权 | 三种入口共享任务记录、页面绑定、取消、执行确认及失败保护 |

飞书“仅发送”不能替代 F5；MCP 可用不能替代 F3。V3 完整发布需三条主线分别通过验收。允许分阶段试用，但必须标注已开放能力。

### 3.2 后续增强（P1）

- lark-cli 作为可选飞书连接方式；仅开放经过定义的操作，首批为身份/连接检查和消息发送。不提供任意命令输入。
- 增加第二种本地 Agent 适配，复用相同的产品交互。
- 飞书任务卡片与更丰富的结果格式；在未支持时用可读文本反馈。
- 用户明确选定的多标签页任务；不在 P0 默认暴露全部浏览器内容。

本次建议先交付稳定的应用机器人闭环，再按本机环境增加 lark-cli。lark-cli 是否提升为 P0、首批本地 Agent 是 Codex 还是 Cursor，见待确认项。

### 3.3 本期不做

通用桌面控制、任意终端命令执行、无人值守跨站代理、云端长期任务调度、组织多人协作、共享工具市场、全量飞书办公套件集成、自动下载或安装 Agent、对任意 Agent 的兼容承诺。

## 4. 产品对象与统一规则

| 对象 | 规则 |
|---|---|
| 会话 | 仍围绕一个网页工具组织；每轮记录来源、执行方和关联任务 |
| 任务 | 一次明确请求，有独立身份、目标页面、状态和结果；同一任务可在鲁班查看其外部来源 |
| 执行方 | 第三方模型或已连接的本地 Agent；一轮执行期间不可中途替换 |
| 连接 | 区分本地服务、MCP 客户端、Agent 与飞书连接，不用一个“已连接”代表全部可用 |
| 授权 | 绑定具体连接、能力和页面范围，可查看、撤销；外部入口不继承无限浏览器权限 |
| 制品 | 统一进入现有工具草稿；来源不改变检查、试运行、保存和恢复规则 |

任务状态至少覆盖：等待确认、等待执行、处理中、等待用户操作、已完成、失败、已取消。界面只展示实际发生的阶段；模型结束、消息送达、脚本运行结束与用户确认效果分别表达。

“生成任务完成”表示有效草稿已交付；“页面运行完成”表示运行返回结果；“发送完成”表示飞书通道已确认接收。不能把上述状态描述为用户已读或效果已验收。

## 5. 功能需求

### 5.1 F1：本地连接与能力管理

**用户结果：** 能判断本机能力是否可用，并知道如何恢复。

- 现有第三方模型继续可用；未配置本地连接时，不阻塞原链路。
- 设置中增加“连接与集成”，分别展示本地服务、已授权 MCP 客户端、本地 Agent、飞书。
- 初次连接由用户发起，展示连接对象与拟开放能力；不能仅凭本机访问就自动授权。
- 状态需区分未配置、未启动、待授权、可用、连接中断、版本不兼容，并提供具体下一步。
- 提供连接检查，明确检查覆盖的能力；仅能连接本地服务时不能宣称 Agent 和飞书均可用。
- 用户可断开或撤销授权；撤销阻止新任务和未执行操作，已产生副作用不能假定被撤销。
- 不把密钥、访问令牌或完整凭据放入聊天、错误、日志或普通导出内容。
- 浏览器关闭、本机休眠和服务停止期间不承诺执行任务；重新连接不自动执行积压的写操作。

### 5.2 F2：供本地 Agent 使用的 MCP

**用户结果：** 在本地 Agent 内即可使用鲁班处理授权网页，操作在鲁班中可见。

产品需提供配置说明、连接检查与能力列表。P0 至少在一个真实客户端完成端到端验证；Cursor 与 Codex 分别标注已验证、未验证或不支持，不因其中一个成功就笼统宣称全部兼容。

| 能力类别 | P0 行为 | 约束 |
|---|---|---|
| 页面发现 | 返回用户已开放的页面及可读摘要 | 未开放页面不返回标题、URL 或内容；无目标时请求用户选择 |
| 页面上下文 | 获取指定页面有限摘要、点选目标与必要结构 | 不默认传完整 HTML、Cookie、密码或浏览器存储 |
| 工具查看 | 获取授权工具的当前基线与状态 | 不暴露其他工具会话、凭据或无关页面内容 |
| 草稿提交 | 将生成/修改结果提交为指定工具的候选草稿 | 检查通过才进入可试运行状态，不覆盖保存版 |
| 运行请求 | 提交指定页面、指定版本草稿的试运行申请 | P0 在鲁班中确认后执行；禁止绕过检查和确认 |
| 状态查询与取消 | 查看任务结果、诊断及取消尚未完成的任务 | 区分取消请求已接收与实际停止；迟到结果不能重新覆盖 |

保存、恢复、删除和开启自动运行仍由用户在鲁班完成，P0 不向外提供可直接调用的写入能力。若后续开放，须独立定义授权和确认流程。

外部请求进入鲁班对话记录，展示客户端、任务摘要、页面、请求操作及当前结果。同一客户端重复提交同一请求不得造成重复试运行；新请求操作相同也不能静默视为已经授权。

目标必须绑定具体标签页及页面有效身份。执行前发现导航、页面关闭或上下文过期，停止旧操作并请求重新选择；不能把任务转移到后来成为活动页的其他标签。

### 5.3 F3：鲁班会话使用本地 Agent

**用户结果：** 在熟悉的聊天界面使用本地 Agent，继续修改当前工具。

- 输入区提供紧凑的执行方选择，区分“第三方模型”和“本地 Agent”。默认沿用现有配置，不自动切换。
- 每个本地 Agent 展示名称、连接状态、已支持能力；不可用时说明原因。
- 发送前可查看本轮将提供的用户需求、必要历史、当前草稿/保存基线、页面摘要、有效约束和授权能力。
- 切换执行方不删除当前制品与对话，但不得声称新的 Agent 已拥有完整历史；不能恢复原会话时告知以已有摘要建立新会话。
- Agent 输出继续进入统一聊天与制品浮层，支持处理状态、简短摘要、工具调用摘要、最终解释及代码草稿。不要求展示内部完整推理。
- Agent 生成的代码执行相同质量检查；拒绝不完整产物成为有效草稿，不额外叠加无限自动修复。
- Agent 请求网页写操作时，在鲁班中展示操作范围和确认入口；连接授权不等同于执行授权。
- 请求文件、终端或其他电脑权限时，说明由本地 Agent 自身授权体系管理；鲁班 P0 不自动授予或代为确认这些权限。
- 停止、超时或断连保留旧草稿及保存版；显示已发生的操作，不自动切换第三方模型重发上下文。
- 一项工具同一时刻只接受一个生成/修改任务；外部 Agent 与侧栏同时修改时提示占用或冲突，不静默覆盖。

首批适配对象与具体可用能力须通过验证后公布。若某客户端只能作为 MCP 调用方，不能同时宣称它可作为鲁班会话执行方。

### 5.4 F4：发送内容到飞书

**用户结果：** 将当前任务结果或选定网页信息发送到明确的飞书目标。

- 支持发送用户选择的文本摘要、脱敏网页链接和任务结果；完整代码与页面内容不默认附带。
- 发送入口位于结果的更多操作，点击后展示接收目标、实际正文及附件范围，确认后发送。
- 用户能配置连接名称、目标说明并检查可用性；凭据按实际通道配置，敏感字段默认隐藏。
- 区分仅能推送消息的连接与可接收指令的应用机器人；设置中明确能力差异。
- 只显示通道已确认的结果；失败保留内容，允许手动重试。送达未知时明确提示，避免重复重试造成多条消息。
- 发送被拒绝、目标不可用或授权失效时提供修复入口，不把失败归因于模型。
- lark-cli 方式如进入本期，需显示实际发送身份与目标；沿用本机授权，不要求用户把 CLI 登录凭据复制给模型。

### 5.5 F5：从飞书机器人发起任务

**用户结果：** 向机器人提出网页任务，在飞书查看反馈，在鲁班确认浏览器操作。

P0 建议先支持与已授权用户的单聊。群聊、多人共享浏览器和任意群成员下发指令不进入默认范围。

1. 用户完成机器人连接和发送者绑定；只接受已绑定身份，不以展示昵称识别用户。
2. 用户发消息后，机器人回复任务已接收或无法接收；展示可追踪的任务标识。
3. 目标页面沿用用户明确指定的绑定。没有绑定、存在多个候选或页面已失效时，请求在鲁班选择，不能猜测当前活动页。
4. 明确需求后，以用户为该连接选定的执行方处理；未配置执行方则等待配置，不默认使用某个付费模型。
5. 只读分析在已授权范围内完成；脚本生成返回待试运行草稿。涉及网页写操作，飞书回复“等待在鲁班确认”，不因一条自然语言消息跳过确认。
6. 最终回复简短结果、失败原因或所需操作。未授权上传完整页面、代码与会话历史时，不自动回传这些材料。
7. 用户可查询状态或取消任务。后续消息未明确关联任务且存在多个任务时，先澄清，避免写入错误会话。

重复事件只处理一次；机器人自己的回复不触发新任务。断线后不把历史消息全部当作新指令执行。任务执行成功但回传失败时，记录“任务已完成，回复失败”，重试只回传结果。

### 5.6 F6：统一授权、上下文与异常恢复

- 页面内容、飞书消息和外部 Agent 返回值均为任务数据，不能自行修改鲁班权限、授权范围或安全规则。
- 接入第三方渠道后继续执行脱敏和上下文预算；不因“本地 Agent”而默认允许全部原始页面数据。
- 新连接默认无页面访问权限；用户明确选择后开放。P0 建议授权到指定页面/工具，持久授权必须单独开启并可撤销。
- MCP 调用、Agent 操作与飞书任务记录来源、目标、授权决定、可获得结果；敏感内容不进入普通诊断日志。
- 外部发送与页面执行分别确认；一次同意试运行不授权发送飞书，一次同意发送不授权浏览器操作。
- 关闭侧栏是否仍能处理只读任务应按实际运行能力说明；需要用户确认时保持等待，不以超时默认同意。

| 异常 | 产品行为 |
|---|---|
| 本地服务/Agent 不可用 | 保留输入与制品，提供启动/重连说明；不自动切换执行方 |
| 无页面或有多个候选 | 等待明确绑定，不读取所有标签页来猜目标 |
| 导航、页面关闭、目标失效 | 旧操作失效，重新采集后再确认 |
| 多入口同时修改 | 明确任务占用或版本冲突，保留各自结果供选择 |
| 用户取消后结果返回 | 标记迟到，不更新有效草稿或发送新的结果消息 |
| 本地 Agent 仍未停止 | 展示停止未确认与后续可获得状态；不能虚假显示已完全终止 |
| 飞书事件重复或发送状态未知 | 去重接收；发送未知可查询则查询，否则提示用户核对 |
| 浏览器重启、电脑休眠 | 恢复记录，未完成写操作重新确认，不自动重放 |
| 权限撤销 | 阻止后续访问和执行，保留必要记录，允许清除本地历史 |

## 6. 页面与交互要求

延续 V2.1 R2 的聊天布局，不增加常驻控制台或多张设置表单。

| 位置 | 新增内容 | 交互规则 |
|---|---|---|
| 固定输入区 | 执行方选择及简短可用状态 | 选择器按需展开，执行期间不可切换当前轮 |
| 聊天流 | 外部来源标识、任务进度、待确认操作 | 技术详情折叠；确认区显示目标页面和影响范围 |
| 制品浮层 | 来源、对应任务、草稿状态 | 沿用检查、运行、保存，不增加第二套版本体系 |
| 结果更多菜单 | 发送到飞书 | 先预览接收目标与内容 |
| 设置：连接与集成 | 本地连接、MCP 客户端、Agent、飞书 | 各自展示状态、检查、授权与撤销入口 |
| 按需任务记录 | 来源、执行方、页面、状态、时间、结果 | 可从外部任务消息进入，无需新建一级导航 |

待确认请求不抢焦点、不自动执行；窄侧栏能完整看到目标、主要风险与确认/拒绝按钮。状态不能只靠颜色，键盘可操作，长诊断默认折叠。

## 7. 初始化、升级与数据规则

- 升级不改变现有模型、脚本、草稿、上一版、自动运行开关和网站范围。
- 本地连接、MCP 与飞书初始为未配置；不自动安装依赖或开放浏览器访问。
- 旧消息不强制补造来源、执行方或任务身份，可标为历史记录。
- 删除连接同时撤销其授权；明确是否保留任务历史。删除连接不删除用户已保存的网页工具。
- 外部返回内容不能包含可自动生效的权限变更；权限变化必须进入已有授权流程。
- 普通脚本导出仍只包含可独立运行的脚本，不包含 MCP、Agent 或飞书凭据；依赖外部连接的附加能力需明确说明，不能假称完全可移植。

## 8. 验收标准

以下场景均需保留真实环境、客户端/Agent 版本、操作记录、结果与已知限制；仅模拟通过不算第三方兼容验收。

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A1 | 原能力回归 | 未配置任何连接仍可完成第三方模型生成、修改、试运行、保存与恢复 |
| A2 | 本地会话 | 一个真实本地 Agent 完成新建和至少两轮修改，沿用当前草稿，不串工具 |
| A3 | Agent 质量保护 | 无效或不完整代码不能运行/保存；失败不覆盖旧版 |
| A4 | MCP 只读 | 一个真实客户端读取用户指定页；未授权页面不出现在结果中 |
| A5 | MCP 修改 | 客户端提交草稿，鲁班可查看来源；未经确认不运行，确认后运行对应版本 |
| A6 | 飞书发送 | 用户预览并确认后目标收到选定内容；失败与未知状态有清晰反馈 |
| A7 | 飞书任务闭环 | 已绑定用户发起任务，鲁班处理，飞书收到结果或待确认提示 |
| A8 | 页面绑定 | 多页、导航和关闭场景均不会执行到错误页面 |
| A9 | 重复与并发 | 重复事件不重复执行；两入口改同一工具不覆盖未确认结果 |
| A10 | 取消与恢复 | 取消、断线、重启后的迟到结果不覆盖草稿，写操作不自动重放 |
| A11 | 授权隔离 | 未绑定发送者、未授权客户端与已撤销连接均不能访问页面或执行 |
| A12 | 数据与回传 | 实际发送内容符合预览及授权，日志与导出无凭据，结果回传失败不重跑任务 |

不预设成功率、延迟或用户增长数字。先记录各入口的任务完成情况、连接失败原因、等待确认次数、取消有效性、误执行与重复执行情况，再由试用结果确定指标目标。误页执行、未授权读取、未确认写入与已保存代码被静默覆盖属于发布阻断问题。

## 9. 建议交付顺序

| 阶段 | 交付内容 | 出口 |
|---|---|---|
| 1 | 本地连接、授权、页面绑定、任务记录 | 连接/断开/撤销及原链路回归通过 |
| 2 | MCP 只读与草稿/运行申请 | 一个真实客户端完成读取到确认试运行闭环 |
| 3 | 本地 Agent 会话执行 | 一个真实 Agent 完成生成、修改、取消与失败保护 |
| 4 | 飞书发送与应用机器人入口 | 单聊发起、鲁班确认、结果回传全链路通过 |
| 5 | 集成验收及可选 lark-cli | 并发、重启、去重、撤销通过；分别声明已验证兼容范围 |

阶段不等于研发排期。技术方案需另行验证浏览器与本机连接、第三方运行模式、机器人接收机制及分发安装方式，不在本需求中预定实现。
