# Luban 开发规则

## 技能使用约定

- 本项目后续不再使用 `lkcli/*` 下的任何技能，包括该目录下的嵌套技能。
- 不因需求分析、PRD 编写、研发或文档归档自动触发这些技能及其团队、产品线、模板、LUCP 关联或 AI 度量确认流程。
- 本约定适用于整个 Luban 项目；除非用户明确撤销，否则持续有效。

## 通用能力边界（必须遵守）

- Luban 提供通用网页理解、目标引用、范围选择、标注、计划、授权、执行和效果检查能力。
- 禁止在产品代码、系统提示词、默认配置中硬编码某个网站的域名、元素 ID/class、选择器、接口或专属布局规则。
- 禁止把广告识别、广告容器归并、广告残留扫描等任务语义写入底层页面工具或 Harness。具体目标由 Agent 根据用户需求和真实页面证据分析、提出，并由用户确认。
- 网站和广告场景只能作为测试夹具、回归案例或验收材料；禁止把测试夹具变为运行时站点适配器。
- 允许依据当次真实页面证据动态产生目标选择器和用户确认的脚本草稿；这些属于任务制品，不得回灌为产品预置规则或长期站点适配代码。
- 页面工具提供有界结构证据、属性、关系、位置及覆盖范围，不把结构候选直接判定为业务目标；采集截断、iframe/Shadow DOM 等不可见范围必须明确。
- 元素或处理范围发生变化后必须重新验证，不能通过某网站的“稳定指纹”绕过失效检查。通用定位必须验证唯一性及节点身份。
- 验收同时检查确认目标的预期变化和未授权区域的保留情况；执行完成、目标不可见、局部计划通过均不等于用户的完整语义目标已达成。
- 生成、运行、保存分别授权；分析和普通聊天不得自动生成或执行脚本。
- 完整的人类改造请求可记录生成意愿；核验需求、真实证据与具体范围确认后，由宿主绑定当前需求/范围/页面/草稿版本批准并自动生成候选，不再泛问是否生成。保存意愿不等于批准；变更撤销旧批准但保留未取消的任务，取消清除意愿。
- 新改造请求统一进入通用 program 候选链路，包括隐藏、弱化；旧固定编译器仅作兼容入口，不按动作划分产品能力。
- 修复必须补充通用反例和跨布局测试，不允许只针对某网站补特判。交付前检查运行时代码和提示词是否残留站点/任务特判。

## 通用脚本生成架构

- 页面改造通过 Agent 基于真实证据生成通用程序；删除、替换、添加、修改、统计和组合是验收场景，不为每个场景增加业务工具或站点适配。
- hide/dim 固定编译器仅是旧实现或可选内部快路径，不是产品能力边界；不得要求所有通用候选都与旧编译器输出逐字相等。
- 通用候选必须绑定需求、证据、页面/范围版本、生成批准和草稿基线。绑定通过不等于代码安全、范围隔离、效果通过或运行许可。
- 不能通过移除旧校验直接执行任意模型代码；通用运行链路须先通过隔离、能力代理、目标及保留范围、资源限制和效果验证，再切换部署。
- 验收按用户目标与保留条件判定，固定动作拒绝测试只能证明旧边界，不能证明通用场景通过。新契约、架构设计、已接入、已实机验收四种状态必须分开标注。
- 架构与迁移门槛见 [通用脚本架构](docs/v4.3/54-generic-script-architecture-2026-10-28.md)。

## 文档与验收

按阶段输出 Markdown 执行计划、实施与验收记录、复核记录和整体报告。自动验收失败时自行修复；真实浏览器或模型未验证的部分必须明确标记，不能沿用旧版本验收结论。

## 产品与扩展版本

- 产品阶段 Vx.y 与 Chrome 扩展版本 `0.x.y` 同步，例如 V4.3 → 0.4.3、V4.4 → 0.4.4、V5.0 → 0.5.0。推进产品大版本/阶段时主动更新 manifest、package 及 lock 根包版本，并构建核对 dist manifest；普通修复不自动推进阶段。
- 内部包、协议和数据库 schema 版本独立管理，不机械联动。详细规则见 [Luban 版本同步规则](../.cursor/rules/luban-version.mdc)。
